# Intent: mcp-remote router must import on the locked mcp 2.x

## Problem

`requirements.lock:1629` pins `mcp==2.0.0`, and an unpinned install of the
two `requirements.txt` files resolves mcp 2.x too (mcp arrives only through
`graphifyy[mcp]`, `apps/backend/requirements.txt:52`). The lowlevel
`mcp.server.lowlevel.Server` in 2.x has no `list_tools()` / `call_tool()`
decorators: handlers are passed to the constructor (`on_list_tools=`,
`on_call_tool=`) and take `(ctx, params)`. So
`apps/web-server/server/mcp_remote/server.py:56` raises
`AttributeError: 'Server' object has no attribute 'list_tools'` at import.

`server/main.py:640-645` imports that module inside `create_app` only when
`AIFACTORY_MCP_REMOTE_ENABLED=true`, so any deployment that turns the remote
MCP transport on fails to start. No test imports the module, which is why CI
(mcp 2.x) stayed green and local venvs (mcp 1.27) never showed it.

#1816 worked around it by forcing the flag off in both runs of
`scripts/generate-openapi-spec.py:54-55`, so `openapi-optin.yaml` leaves out
the `/api/mcp-remote/*` paths.

## Proposed outcome

- With `AIFACTORY_MCP_REMOTE_ENABLED=true` the web-server starts on the
  locked deps and mounts `/api/mcp-remote/sse` and `/api/mcp-remote/messages/`.
- A CI test builds the app with the flag on, so this cannot regress silently.
- The generator override is gone; `openapi-optin.yaml` includes the two
  mcp-remote paths; the TechDocs drift checks stay green.

## Affected users and systems

- `apps/web-server/server/mcp_remote/server.py`, a new test under
  `apps/web-server/tests/`, `scripts/generate-openapi-spec.py`,
  `apps/web-server/openapi-optin.yaml`, the docs that say mcp-remote is left
  out (`docs/api.md`, `catalog-info.yaml`).
- Operators who enable the remote MCP transport.

## Constraints

- Check the real installed 2.x API (done in a scratch venv with `mcp==2.0.0`);
  do not guess.
- Behaviour unchanged: same tool catalog, same auth (contextvar set per SSE
  connection), unauthenticated tool calls still refused.
- Small; no deploys.

## Open questions

1. Support mcp 1.x as well? Conservative choice: no. The lock is what ships;
   declare the floor `mcp>=2.0` in `apps/web-server/requirements.txt` (the
   web-server imports mcp directly) so a 1.x env fails at install, not at
   runtime.
