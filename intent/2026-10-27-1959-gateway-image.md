# Intent: model gateway image, built and signed in CI (Factory#1959 Stage 0a)

## Problem

Epic Factory#1959 needs a model access gateway that every service calls
instead of holding provider keys. The 2026-10-26 wave shipped the groundwork:
AIFactory #1886 and TFactory #1447 pin which credentials reach dispatched Jobs,
and AIFactory #1896 resolves contract route tiers from a mounted catalog (flag
off). The next slice in the epic plan is the gateway image: a first-party
container, built and cosign-signed by CI, deployed nowhere.

None of it exists yet. Checked 2026-10-27:

- There is no gateway source in any repo.
- AIFactory already ships an optional LiteLLM sub-chart
  (`charts/aifactory/Chart.yaml`, `litellm-helm` 1.86.2 from
  `oci://ghcr.io/berriai`, off by default) and a client seam
  (`apps/backend/providers/_gateway.py`, `LITELLM_GATEWAY_URL`). The epic plan
  rejects that upstream image because Kyverno does not verify third-party
  images.
- Kyverno (`factory-gitops/.../verify-factory-image-signatures.yaml`) admits a
  signed image only by its image glob plus the signer's subject,
  `^https://github.com/olafkfreund/AIFactory/.github/workflows/(deploy|release|build-nix)\.yml@refs/heads/main$`
  for `ghcr.io/olafkfreund/aifactory:*`.

## Owner decisions (2026-10-27)

1. **The gateway is a second image built in AIFactory**, by its
   `deploy.yml` / `release.yml`, not a new repo.
   **Accepted risk:** the gateway shares AIFactory's signing identity. A
   compromised AIFactory workflow could sign a gateway image as well as an
   AIFactory one, so the gateway does not get a separate supply-chain trust
   anchor, and its release cadence is tied to AIFactory's. The owner chose
   this over a new `olafkfreund/model-gateway` repo. The runtime trust
   boundary (own namespace, egress allowlist) is unaffected and is still
   required at deploy time.
2. **In-house stdlib gateway, as the epic plan says.** AIFactory's LiteLLM
   sub-chart is **deprecated** in this slice (marked in the chart and the
   docs). Removing it is a later slice.

## Proposed outcome

A gateway image is built and Trivy-scanned on every AIFactory PR. On every
AIFactory deploy and release, it is pushed and signed keylessly by digest (and
SBOM-attested on release), the same way the existing three images are. It can
be verified with `cosign verify` against AIFactory's workflow identity. It runs
a minimal Plane A (OpenAI-shaped) pass-through with a health endpoint, and
nothing calls it. The LiteLLM sub-chart reads as deprecated wherever an
operator would turn it on.

## Affected users and systems

- AIFactory: new gateway source, Dockerfile, tests; `image-build.yml`,
  `deploy.yml`, `release.yml`; LiteLLM chart comment and concept doc.
- GHCR: new tags for the gateway image.
- Not affected: any running service, the AIFactory app image, factory-gitops,
  the cluster.

## Constraints

- First-party image signed by our own workflow identity, so admission can
  verify it.
- Stdlib-only Python, like the other in-house proxies.
- No deploy, no gitops pin, no credential touched or rotated. AIFactory
  3.10.11 is mid-deploy.
- Signing only happens on `main` (the Kyverno subject pins `refs/heads/main`).
  A PR into `dev` proves the build, scan and tests; the first signature
  appears when `dev` is released to `main`.
- Must not change what the existing app, `-rmux` and `-nix` images contain or
  how they are pinned.
