# Intent: close the last in-pod agent paths (slice D of #1932, #2095)

## Problem

`AIFACTORY_FORBID_INPOD_AGENTS` (AIFactory#2089) refuses in-pod agents for spec creation, builds, PR
review and clarification. Five more paths still start an LLM session in the web-server pod as the
server uid, and factory-gitops#372 turns FORBID on in production:

- `POST /tasks/{id}/apply-correction` runs the QA fixer (`apps/backend/qa/correction.py`). This is the
  TFactory to AIFactory hand-back in the PARR loop.
- Insights chat (`insights_service.send_message`, all providers) and "generate task from chat".
- Changelog generation (`changelog_service.start_generation`).
- AI merge-conflict resolution (`conflict_service`, two sync methods).
- The settings probe (`routes/settings.py` `_run`) runs `--version` and `pgrep`, not an agent.

## Proposed outcome

With FORBID on, none of the agent paths above can spawn in-pod. Each one is
refused (a Job path is out of scope where it is not sound) with a clear message. Nothing is refused silently: the PR and the docs list every path that
stops working in production.

## Affected users and systems

AIFactory web-server. Production behaviour changes once factory-gitops#372 is live: insights,
changelog, AI conflict resolution and apply-correction stop working unless given a Job path.

## Constraints

No factory-gitops edits. No in-pod fallback when a Job flag is on. Defaults unchanged when FORBID is off.
No live-cluster actions.

## Open questions

None. Owner delegation 2026-11-17: take the least risky recommended option per path.
