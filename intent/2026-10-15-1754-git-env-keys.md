# Intent: git config and exec env keys must not bypass the git checks

## Problem

Open on `dev` at `357e6d95`; no commit mentions #1754. The git validator
refuses `git -c core.fsmonitor=…`, `git config core.sshCommand …` and
similar (#1689, #1720), but it only sees the `git` argv. The same config and
program choices can be set through the environment, which nothing checks:

- `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.fsmonitor GIT_CONFIG_VALUE_0=x git status`
  is allowed, bare and as `env … git status`.
- `GIT_SSH_COMMAND`, `GIT_EXEC_PATH`, `GIT_PROXY_COMMAND`, `GIT_EXTERNAL_DIFF`,
  `GIT_ASKPASS`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_GLOBAL`, `GIT_DIR`, … run a
  program or load config the `-c` checks would refuse.
- `export GIT_CONFIG_COUNT=…; git status` sets it for every later command;
  `export`, `read`, `printf -v` and `let` are allowlisted
  (`project/command_registry/base.py`) and can set a variable by name, also a
  dynamic one (`export $K=…`).

In `apps/backend/security/ast_parser.py`, bashlex gives prefix assignments as
`assignment` nodes, which `_command_words` (`:144`) drops; `_unwrap_env`
(`:295`) skips `VAR=val` words; no builtin's arguments are inspected.

## Proposed outcome

- Setting a git config or exec key in any form (prefix assignment, standalone
  assignment, `env`, `export`/`read`/`printf -v`/`let`, inside `bash -c` or a
  substitution) is refused.
- The rule is fail-closed: every `GIT_*` key is refused unless it is on a short
  allow list of keys that change neither config nor what runs.
- `GIT_PAGER=cat git log`, `GIT_AUTHOR_NAME=x git commit`,
  `GIT_EDITOR=true git rebase --continue`, `FOO=$BAR git status` and
  `export PATH="$HOME/bin:$PATH"` stay allowed.

## Affected users and systems

- `apps/backend/security/ast_parser.py`; callers `security/hooks.py`,
  `security/plan_commands.py` (no change).
- `tests/test_command_sandbox.py`.
- Agents that set other `GIT_*` keys (e.g. `GIT_TRACE`): now refused.

## Constraints

- Fail closed; allow lists, not lists of known-bad forms (#1782's lesson).
- Keep `MUST_PARSE` exact-name tests green.
- Out of scope: #1783 (redirect targets), #1797 (`${…}`, heredocs), #1784
  (wrappers), #1745 (agent-writable config files).

## Open questions

1. Non-`GIT_*` keys git reads (`EDITOR`, `VISUAL`, `PAGER`, `SSH_ASKPASS`),
   and keys that redirect files or binaries (`HOME`, `XDG_CONFIG_HOME`,
   `PATH`, `LD_PRELOAD`). Taken here: restrict the editor/pager keys to
   no-op values, refuse `SSH_ASKPASS`, leave the file/binary redirects as
   trusted file content (#1782's boundary).
