# Intent: upload LFS objects on the remaining push sites and ship git-lfs

Not fixed on dev. Checked at `357e6d95`. Follow-up to #1690
(`intent/2026-10-10-1690-lfs-push-hooks-off.md`).

## Problem

Hooks are off since #1680, so git-lfs's `pre-push` hook no longer uploads
LFS objects. #1690 added an explicit, pinned `git lfs push` before the
web-server PR pushes (`push_with_lfs`,
`apps/web-server/server/services/pr_endgame.py:81-111`, and an inline copy
in `apps/web-server/server/routes/pr.py:322-368`). Still missing:

1. `Dockerfile:175-187` (Wolfi apk list) has no `git-lfs`, so the default
   image skips the LFS step everywhere (`lfs_push_argv` returns None when
   `git-lfs` is not on PATH, `apps/backend/core/child_env.py:99`).
2. `apps/backend/core/workspace_fetch.py:135-146` pushes the build branch
   from the build Job with a plain `git push`.
3. `apps/backend/pfactory/tfactory_client.py:382-396`
   (`_git_info_and_push`) pushes the build commit for TFactory with a plain
   `git push`.

A repo that tracks files in LFS gets a branch whose pointers have no objects
on the server.

## Proposed outcome

- The image ships git-lfs with a `>=` version floor that exists in the
  Wolfi index the pinned base uses.
- Every push site uploads LFS objects before the ref push, with the same
  pinned endpoint and the same `lfs.customtransfer.*` / `url.*` refusal as
  #1690. A failed upload is a push failure at that site.
- Nothing that works today breaks:
  - a repo that does not use LFS (no `filter=lfs` in its `.gitattributes`)
    runs no LFS step at all;
  - a slow upload on an LFS repo is not cut off by the 60-180 s push
    timeouts;
  - the build Job push stays best-effort: an LFS failure logs and returns
    False, it never fails a green build (`workspace_fetch.py:111`);
  - clones and checkouts in the image keep working when LFS objects cannot
    be downloaded.

## Affected

- `Dockerfile` (runtime stage apk list)
- `apps/backend/core/child_env.py` (shared helper)
- `apps/backend/core/workspace_fetch.py`, `apps/backend/pfactory/tfactory_client.py`
- `apps/web-server/server/services/pr_endgame.py`, `apps/web-server/server/routes/pr.py`
  (they gain the uses-LFS gate and the longer upload timeout)
- tests: `tests/test_lfs_push.py`, `tests/test_create_pr_fetches_branch.py`, a new site test

## Constraints

- Reuse `lfs_push_argv`; one shared upload routine, no fourth copy.
- No token in argv or env (#1366, #1723); the push env from
  `authed_push_url` / `github_env` is reused for the upload.
- The apk floor must exist in the Wolfi index, or the image build fails.

## Open questions

- None blocking. The Wolfi `git-lfs` package writes system-wide
  `filter.lfs.*` config (smudge on, `required=true`), which would make
  clones download LFS objects and fail when they cannot. Conservative answer,
  carried to the spec: install it with `--skip-smudge`.
