# Intent: fix the AIFactory findings from the 2026-11-23 UI test

## Problem

The browser UI test of prod (Factory#3873, AIFactory#2198) found these
AIFactory bugs:

- The owner gets 403 on their own project's environment settings
  (`GET /api/projects/{id}/env`). That breaks the MCP view and Project
  Settings → General.
- SSO users are provisioned as `member`, so the owner has no admin rights.
- Settings shows "Version 1.0.0-web" while the server is 3.21.1.
- Agent settings fire 409s for unconfigured providers.
- Add Project opens on a `/home` local folder with an error.
- The board lights "Review" with 0 items.
- The agent profile shows "Auto" as chosen while unset.
- Chat keeps empty sessions.
- The Index view shows pod paths.

## Proposed outcome

Each of those screens shows the right thing for the owner, with no 403, no
409 noise and no misleading state. The owner holds an admin-level role
through their identity-provider group. A browser re-test of each touched
screen comes back clean.

## Affected users and systems

AIFactory web server and frontend; gitops (OIDC role mapping); the owner and
any SSO user.

## Constraints

- Secrets (git tokens) are never returned to non-admins.
- PATCH stays admin.
- D6 is unchanged: unknown and invisible projects get the identical 404.
- No new features: bug fixes only (owner rule: UI fixes before features).

## Open questions

None. Root causes are in Factory#3873's plan.
