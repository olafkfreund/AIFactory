# Intent: spec Job soak evidence and hard-disable of in-pod agents (#1930, #1932)

## Problem

Owner decision 2026-10-31 (option B): every LLM agent session in prod runs as a Kubernetes Job; the in-pod subprocess backend is local-dev only. Spec creation as a Job is live (`AIFACTORY_SPEC_BACKEND=kubejob`, factory-gitops#349) but was blocked by the netpol-gate (Factory#3770, now closed). Nothing yet stops a misconfigured or fallen-back deployment from running an agent in the control-plane pod again.

## Proposed outcome

- Evidence recorded that a spec creation completes as a Job (Factory#3770 proof: Job `factory-aifactory-f-3770-spec-069bec38`, Complete 1/1 in 82s; deployed image is 3.12.0).
- A default-off switch refuses the four in-pod agent spawn paths that exist today (spec creation, build, PR review, clarification), at the subprocess boundary so retries and queued starts are covered unless the deployment says it is local dev. It stays off in prod until the soak is evidenced.

## Affected users and systems

AIFactory web-server spawn sites; factory-gitops later flips the switch (separate, after soak).

## Constraints

Default off, so releasing it changes nothing in prod. No cluster mutation. Insights, changelog and settings probe spawns stay with slice D (out of scope here).

## Open questions

None. Decision (owner delegation 2026-11-17): name the switch `AIFACTORY_FORBID_INPOD_AGENTS`, with `AIFACTORY_LOCAL_DEV=1` as the explicit local-dev escape; chosen because it is opt-in (least risky to operate) and mirrors `APP_REQUIRE_ENV_SECRETS`.
