# Intent: required checks must pass again, and must not depend on a vendor's goodwill

## Problem

Four required checks fail on **every** open PR, so nothing can merge — including
the dependency bumps that might otherwise carry a fix. Last green on `dev` was
2026-09-24 10:04Z; every run since 2026-09-24 21:34Z is red. #1611, #1610 and
#1609 fail identically, and two of those are dependabot bumps that touch no
Python.

There are two independent causes.

### 1. MinIO's images are no longer publicly pullable

`.github/workflows/ci.yml:80` starts MinIO with
`docker run ... quay.io/minio/minio:latest`, which now fails:

```
docker: Error response from daemon: unauthorized: access to the requested
resource is not authorized
##[error]Process completed with exit code 125
```

This is not a transient registry hiccup and not specific to quay: an anonymous
token for `minio/minio` is issued but every manifest request returns 401, and
even the tag list is denied. `docker.io/minio/minio:latest` returns 401 as well.
The image has been gated everywhere, so there is no registry to move to — the
dependency itself has to change.

The workflow already anticipated an unavailable MinIO. Its own comment says the
integration tests "would just skip in that case". They do not: `docker run`
exits 125 first and takes the whole job with it, so a lint-and-unit-test job
turns red over an object store it only needs for one group of tests. That is the
same defect class as #1365 — a step whose failure mode is worse than the thing it
guards.

This is the second time this has bitten: the step's comment records that
`bitnami/minio:latest` was retired mid-2026, which is why it points at quay now.
Fixing the registry again without fixing the fragility would just queue up a
third outage.

### 2. The postgres tests depend on SQLAlchemy's default driver

```
sqlalchemy/dialects/postgresql/psycopg.py:497: in import_dbapi
    import psycopg
E   ModuleNotFoundError: No module named 'psycopg'
```

Seven copies of `_sync_url()` across `tests/postgres/` each do
`url.replace("+asyncpg", "")`, turning `postgresql+asyncpg://…` into a **bare**
`postgresql://…` and leaving the driver to SQLAlchemy's default. That default
changed: 2.0 resolves `postgresql://` to psycopg2, which
`tests/requirements-test.txt:37` installs; 2.1 resolves it to psycopg v3, which
nothing installs. `apps/web-server/requirements.txt:60` declares
`sqlalchemy[asyncio]>=2.0.0` with no upper bound, so CI took 2.1 as soon as it
existed.

Every postgres test that opens a connection fails, on both PG 15 and PG 16,
while the `test_p1_alembic.py` tests that never connect all pass — which is what
identifies the driver rather than the schema as the cause.

This is a latent defect the upgrade merely revealed: the suite never said which
driver it wanted. It also hides from local runs, where an older SQLAlchemy is
already installed, so the failure appears only in CI.

## Proposed outcome

- The required checks pass again on PRs that deserve to pass, so merges unblock.
- The S3 integration tests run against an object store that can actually be
  pulled, and if the object store is ever unavailable again the affected tests
  **skip visibly** rather than failing the whole job — and a skip is reported,
  not silent.
- The postgres tests name the driver they need, so a library's default cannot
  decide whether CI passes.
- A local run and a CI run agree, instead of diverging on an unpinned floor.

## Affected users and systems

- `.github/workflows/ci.yml` — the `backend (ruff + pytest)` and
  `postgres (P1 acceptance)` jobs.
- `tests/postgres/` — the seven `_sync_url()` copies, and `helpers.py`.
- `tests/requirements-test.txt` and/or `apps/web-server/requirements.txt`.
- Everyone with an open PR: three today, and every future one until this lands.
- No production code, no runtime dependency, no deployment.

## Constraints

- **A skipped test must be visible.** Making the MinIO step tolerant must not
  quietly delete S3 coverage; that would trade a red job for a false green, which
  is worse. The same rule as #597 and #1496.
- Any replacement object store must be S3-compatible enough for the existing
  tests without rewriting them, and must be anonymously pullable — the property
  whose absence caused this.
- Prefer pinning by digest over `:latest`, so a vendor's next policy change is a
  deliberate bump rather than an outage.
- The postgres fix must be explicit about the driver rather than pinning
  SQLAlchemy down, so the suite stays upgradeable; if a pin is used as well it
  should be a considered ceiling, not a freeze.
- Fix the duplication once: seven identical `_sync_url()` copies is why this
  needed seven edits instead of one.
- No production dependency may change to fix a test-only problem.

## Open questions

1. **Which object store replaces MinIO?** `adobe/s3mock` (purpose-built for
   tests, lightweight, no real auth), `chrislusf/seaweedfs` (a real S3 server
   with credentials) or `localstack/localstack` (heavier, broader). All three
   pull anonymously today. The right answer depends on whether the S3 tests
   exercise credentials and error semantics or merely object put/get — I will
   determine that from the tests before the spec proposes one.
2. **Pin SQLAlchemy as well as naming the driver?** Naming the driver fixes the
   failure. A ceiling would also catch the *next* default change, at the cost of
   a stale pin. My inclination is to name the driver and not pin, but flag it.
3. **Should the MinIO-unavailable skip be allowed on `main`?** Tolerating a
   missing object store is right for a PR, but a release build arguably should
   fail rather than silently skip its S3 coverage. Worth deciding rather than
   defaulting.
