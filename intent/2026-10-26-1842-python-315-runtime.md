# Intent: move the runtime image to CPython 3.15

## Problem

The runtime image is pinned to a `cgr.dev/chainguard/python:latest-dev` digest
that ships CPython 3.14. Every newer Chainguard digest ships 3.15, so the base
cannot take security rebuilds, and Dependabot is told to ignore it (#1756).
On 3.15, four locked packages (tree-sitter, pyyaml, real-ladybug, xmlsec) have
no cp315 wheel, and ten more need a newer version to get one.

## Proposed outcome

The image builds on a current 3.15 base digest, installs the hash-pinned lock,
and starts and answers `/api/health`. `real_ladybug` (Graphiti memory) and
`xmlsec` (SAML) import and work. Dependabot tracks the base again.

## Affected users and systems

The AIFactory runtime and `build-runtime` images (Dockerfile), `requirements.lock`,
the `deps-lock-drift` CI job, `.github/dependabot.yml`, and the Trivy P0 docker gate.

## Constraints

- Keep `--require-hashes`. No unpinned package enters the venv.
- Keep the existing apk CVE floors and the vendored-npm overlay pins.
- Trivy P0 docker gate stays green; any new CVE is fixed in the same PR.
- Compilers and `-dev` headers must not grow the runtime image.

## Open questions

None. The build path was probed on 2026-10-24 (issue comment); the user pre-approved it.
