# The PARR pipeline and its guards

> Status: the guarded closed loop — **plan → build → deploy → verify → merge**.
> Most guards are opt-in and default OFF; every uncertain step degrades to a
> human-stop rather than guessing.

AIFactory is the build leg of the PARR pipeline (Plan · Act · Reflect · Review).
A task enters as a spec and leaves as a verified, merge-ready change. What makes
it safe to run autonomously is the set of **guards** layered along the path —
each one either enforces an invariant or stops for a human when it can't.

This guide walks the pipeline stage by stage and names the guard at each point.

## The loop

```
Plan        spec + acceptance criteria, plan approved before code
  │
Act         coder/QA loop in an isolated worktree (optionally parallel waves)
  │
Deploy      deterministic Terraform → AWS App Runner (opt-in)
  │
Reflect     verify against the LIVE endpoint, not a diff
  │
Review      PR → reviewer gate → bounded auto-feedback → merge → re-test
```

## The guards

### Plan

- **Spec-first gate.** Every run starts from a written spec with acceptance
  criteria; there is no "vibe" path. You approve the plan before any code is
  written.
- **Trusted-plan signature.** When a plan arrives signed from an upstream
  authority (e.g. PFactory), it is verified with an HMAC key
  (`AIFACTORY_TRUSTED_PLAN_KEY_<AUTHORITY>`) before the fast path skips
  re-planning. A bad signature falls back to planning, it does not execute blind.

### Act (build)

- **Worktree isolation.** Each task runs in its own git worktree on its own
  branch. Nothing touches your working tree until you merge.
- **Parallel-wave invariants.** With `AIFACTORY_PARALLEL`, independent subtasks
  run in isolated sub-worktrees but are **merged sequentially**, and plan state
  stays parent-owned — concurrent coding never races a merge.
- **Act-loop guardrail.** A repeated-failure detector halts an agent looping on
  the same failing edit and escalates instead of burning tokens.
- **Mutation ledger.** Every mutation is checkpointed before it is applied and
  recorded to a ledger, so a bad turn can be rolled back and the claimed-vs-actual
  changes can be audited.

### Deploy (opt-in)

- **Deterministic infrastructure.** The App Runner Terraform is generated by the
  Factory, not an LLM — the same inputs produce the same plan.
- **Teardown always ships with deploy.** The destroy workflow is emitted with the
  deploy workflow; there is no code path that produces one without the other.
- **Cost guard.** Every resource is tagged `factory-ephemeral` + `spec_id`;
  teardown fires on any failure or timeout, and a sweeper removes stragglers
  older than an hour. Teardown can never reach beyond what the Factory created.

See [Deploy-then-verify](https://olafkfreund.github.io/AIFactory/docs/concepts/deploy-then-verify)
for the full mechanics.

### Reflect (verify)

- **Live-endpoint verification.** Tests run against the deployed HTTPS URL, not a
  local process — catching the gap between "it builds" and "it runs."
- **Declared-AC verification.** The signed Task Contract carries the declared
  acceptance criteria, lanes, and endpoints to the verification leg, so it tests
  the declared profile instead of inferring one.

### Review (PR endgame)

- **Reviewer gate.** The pre-merge reviewer is configurable
  (`AIFACTORY_PR_REVIEWER` = `aifactory` | `copilot` | `any`); a `CHANGES_REQUESTED`
  verdict stops for a human.
- **Bounded auto-feedback.** On changes-requested, the fixer runs and the change
  is re-reviewed — but the loop is bounded (≤2 cycles), after which it hands to a
  human rather than looping forever.
- **Merge-conflict stop.** A PR that can't fast-forward updates its branch and
  retries; a genuine conflict stops for a human.

See [`pr-endgame.md`](./pr-endgame.md) for the finish-line detail.

### Throughout

- **OAuth-only by default.** A stray `ANTHROPIC_API_KEY` is scrubbed from agents
  unless an operator explicitly opts into direct-key billing
  (`AIFACTORY_ALLOW_API_KEY`).
- **Hash-chained audit log.** Every action is journaled in a tamper-evident audit
  chain; every spec, plan, and QA report is on disk and in version control.

## Turning the loop on

Every stage past the build is opt-in. A common adoption path:

1. Start with **auto-PR only** (`AIFACTORY_AUTO_PR`) — get the visibility of an
   opened PR, keep a human on the merge button.
2. Add the **`aifactory` reviewer** — no Copilot credits needed — to get an
   automated pre-merge review while still stopping for a human merge.
3. Enable **`AIFACTORY_AUTO_MERGE`** once you trust the reviewer gate on your
   repos.
4. Enable **`AIFACTORY_AUTO_DEPLOY`** last, in staging first, to add the
   live-endpoint verification leg.

See the [Configuration Reference](https://olafkfreund.github.io/AIFactory/docs/configuration-reference)
for every flag and its default.
