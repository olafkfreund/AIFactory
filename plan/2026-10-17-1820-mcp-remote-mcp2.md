# Plan: port mcp-remote to the mcp 2.x server API

Self-contained. You do not need to open the intent or the spec.

**Problem.** `requirements.lock` pins `mcp==2.0.0`. In 2.x,
`mcp.server.lowlevel.Server` has no `list_tools()` / `call_tool()`
decorators, so `apps/web-server/server/mcp_remote/server.py:56` raises
`AttributeError` at import, and `server/main.py:640-645` (flag
`AIFACTORY_MCP_REMOTE_ENABLED=true`) fails to start.
`scripts/generate-openapi-spec.py:54-55` forces the flag off as a workaround.

**Approved decisions.**

1. 2.x API (verified against installed `mcp==2.0.0`):
   `Server(name, *, version=, on_list_tools=, on_call_tool=)`;
   `on_list_tools(ctx, params) -> types.ListToolsResult`;
   `on_call_tool(ctx, params: types.CallToolRequestParams) ->
   types.CallToolResult` (`params.name`, `params.arguments`);
   `CallToolResult(content=[...], is_error=bool)`; `Tool(name=,
   description=, inputSchema=)` still accepted (alias).
   `Server.run(read, write, self.create_initialization_options())`,
   `SseServerTransport` unchanged.
2. 2.x only. Declare `mcp>=2.0` in `apps/web-server/requirements.txt` and
   regenerate `requirements.lock`.
3. Carry the envelope's `isError` to `CallToolResult.is_error`; the
   missing-key path returns `is_error=True`.
4. Remove the generator override; regenerate both specs; update docs that say
   mcp-remote is left out.
