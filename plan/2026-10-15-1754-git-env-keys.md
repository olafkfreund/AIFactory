# Plan: refuse git config and exec env keys wherever a variable is set

Self-contained. You do not need to open the intent or the spec.

**Problem.** The git validator refuses `git -c core.fsmonitor=…` and friends,
but the same config can be set through the environment and nothing checks it:
`GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.fsmonitor GIT_CONFIG_VALUE_0=x git status`
is allowed, bare, via `env`, or via `export …; git status`. Also,
`core/child_env.py:63-75` exports `GIT_CONFIG_COUNT`/`KEY_n`/`VALUE_n` pins
(`core.hooksPath=/dev/null`, `core.fsmonitor=false`, …) into the agent's
environment; unsetting or clearing them is equivalent to
`git -c core.hooksPath=…`.

**Approved decisions** (all in `apps/backend/security/ast_parser.py`).

1. Module constants, near the other wrapper constants:
   - `_SAFE_GIT_KEYS = frozenset({"GIT_AUTHOR_NAME", "GIT_AUTHOR_EMAIL",
     "GIT_AUTHOR_DATE", "GIT_COMMITTER_NAME", "GIT_COMMITTER_EMAIL",
     "GIT_COMMITTER_DATE", "GIT_TERMINAL_PROMPT", "GIT_OPTIONAL_LOCKS",
     "GIT_FLUSH", "GIT_MERGE_AUTOEDIT", "GIT_LFS_SKIP_SMUDGE"})`
   - `_PROGRAM_KEYS = frozenset({"GIT_PAGER", "GIT_EDITOR",
     "GIT_SEQUENCE_EDITOR", "PAGER", "EDITOR", "VISUAL"})`
   - `_NOOP_PROGRAMS = frozenset({"", "cat", "true", ":"})`
   - `_REFUSED_KEYS = frozenset({"SSH_ASKPASS"})`
   - `_VAR_SETTERS = frozenset({"export", "read", "let", "unset", "declare",
     "typeset", "local", "readonly", "mapfile", "readarray", "getopts"})`
   - `_NAME_ASSIGN = re.compile(r"[A-Za-z_][A-Za-z0-9_]*\+?=")`
2. `_env_key_refusal(assignment: str) -> None`: split on the first `=`
   (`name, eq, value = assignment.partition("=")`; strip a trailing `+` from
   name). Allowed when: name in `_PROGRAM_KEYS` and (no `=` or value in
   `_NOOP_PROGRAMS`); else name not in `_REFUSED_KEYS` and (name does not start
   with `GIT_` or name in `_SAFE_GIT_KEYS`). Otherwise raise
   `UnparseableCommand(f"setting {name} can change git config or what git runs; not permitted")`.
3. `_extract` (`:174` loop): for every part of `node` with kind `assignment`,
   call `_env_key_refusal(part.word)`. Do this before the `if not words:
   continue` so a standalone `K=v;` is checked.
4. `_unwrap_env` (`:295`): in the `VAR=val` branch call
   `_env_key_refusal(tok)`. Before `_skip_env_opt` in the option branch, and
   for `tok == "-"` in the `("--", "-")` branch: raise for `-` and
   `--ignore-environment` (and any unique prefix of it, `--i`…), and for a
   short group containing `i` (they drop the pins). For `-u`/`--unset`, take
   the name (attached `-uNAME`, `--unset=NAME`, or the next word) and call
   `_env_key_refusal(name)`.
5. `_skip_exec_opts`: raise for a short option group containing `c`
   (`exec -c` clears the environment).
6. `_emit` (`:186`), after `acc.append(...)`: if `name in _VAR_SETTERS`, call
   `_check_var_setter(words, idx)`; if `name == "printf"`, check only the
   `-v NAME`/`-vNAME` target the same way.
   `_check_var_setter`: for each word after `idx`: if its text starts with
   `-`, require it literal (`_require_literal`) and, for `declare`/`typeset`/
   `local`, raise if it contains `n` (nameref). Otherwise it is a name: its
   `raw` must pass `_static_shape(raw)` or `_NAME_ASSIGN.match(raw)`, else
   raise (dynamic name, e.g. `export $K=1`); then `_env_key_refusal(w.word)`.
   `w.raw` is set in `_extract` for every command word.
7. No caller changes. CHANGELOG entry under Security.

Decision 4's clearing/unset part and 5 are beyond the spec, found while
planning (the `child_env` pins); the spec is updated in this commit.

### Step 4 — review fixes (deviation, added after review)

Review found more ways to set a refused key or run code. All in
`apps/backend/security/ast_parser.py` unless named:

1. `_env_key_refusal`: refuse a name containing `[` (array subscript,
   `GIT_CONFIG_KEY_0[0]=…`), and any name starting with `LD_`
   (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`). This narrows the
   "Not covered" note: `LD_PRELOAD` is now refused.
2. `for NAME in …`: `_collect_command_nodes` also visits `for` nodes; the
   loop variable (the word after `for`) is checked as an assignment with an
   unknown value, so a refused key or a program key (`EDITOR`) is refused.
3. `let` evaluates arithmetic (which can expand `$(…)` in subscripts):
   `_emit` refuses it, it leaves `_VAR_SETTERS`, and it is removed from
   `BASE_COMMANDS` in `apps/backend/project/command_registry/base.py`.
4. `set -a` / `set -o allexport` export every later assignment: `_emit`
   refuses `set` with an option group containing `a`, or an `allexport`
   word. Every word before `--` must be literal (`set $OPTS` could expand to
   `-a`); words after `--` are positional and not checked.
5. `mapfile`/`readarray -C callback` runs the callback: refused for an
   option group containing `C`.
6. `read`, `mapfile`, `readarray`, `getopts` give a bare name an unknown
   value, so a program key (`read EDITOR`) is checked as a non-no-op value.

Tests: `ENV_KEY_PARSER_REFUSED` in `tests/test_command_sandbox.py`
(asserts `UnparseableCommand` from `extract_commands_ast`), plus
`MUST_PARSE` rows for `for f in a b`, `set -euo pipefail`,
`mapfile -t lines`, `LANG=C git status`, `set -- "$@"`.

Check: `pytest tests/test_command_sandbox.py tests/test_plan_commands.py -q`,
`ruff check`, `ruff format --check`.
