## Review changes (PR #1801)

The lead's review asked for these. They change D1-D3 as follows:

- **D1, no silent pointer push:** once the gate passes and `git-lfs` is on
  PATH, a failed get-url or `lfs_push_argv` returning None (GitLab, Azure
  DevOps, `file://`, ssh github origins) returns "LFS repo but no supported
  LFS endpoint for this origin; refusing to push pointers without objects"
  instead of None. Reason: `git lfs install --system` turns the clean filter on,
  so agent commits become pointers. On the packed path, pushing them without
  objects loses the objects for good. With no `git-lfs` binary, the result is
  still None: no clean filter ran, so there are no new pointers.
  Supported LFS repo hosts are therefore github.com over https only. An LFS
  repo anywhere else is now refused rather than pushed incomplete.
- **ssh `git@github.com:` origins are refused, not mapped:** the backend sites
  get no token for non-https remotes (`authed_push_url`). A mapped https LFS
  upload would run without a credential, then fail or wait on a prompt.
- **D2, off the event loop:** `routes/pr.py` moves get-url, the upload and the
  push into a module-level sync `_upload_and_push`, awaited through
  `asyncio.to_thread`. `create_pr_from_task` no longer runs that subprocess on
  the event loop, so ASYNC221 still covers the async function (no nested def
  inside it).
- **D3, threads and timeout:** `build_ingest_payload`, which pushes, is awaited
  through `asyncio.to_thread` in `tfactory_client.py` (auto-handoff) and in
  `routes/execution.py` (handoff route). In `_git_info_and_push`, a
  `TimeoutExpired` from the upload becomes an LFS error, so it returns
  `(url, None)` and logs. It no longer falls into the broad except as
  `(None, None)`.
- **Tests:** a refusal case for each origin in `tests/test_lfs_push.py`, plus a
  case where no git-lfs is installed and the push goes ahead. In
  `tests/test_lfs_push_sites.py`: packed-path GitLab refusal, and the tfactory
  timeout. The fakes in `tests/test_pr_endgame_conflict_loop.py` and
  `apps/web-server/tests/test_pr_endgame.py` (create_pr fetch test) answer
  the gate with "no LFS".

## Review changes, round 2 (PR #1801)

See the spec's Amendment. It supersedes the round-1 "refuse every LFS repo
without an endpoint" rule and D4's `git lfs install --system --skip-smudge`.

- `Dockerfile`: `RUN git lfs uninstall --system` instead. The package's system
  filters are removed.
- `apps/backend/core/child_env.py`: new `enable_lfs_clean_filter(repo)` (D5).
  In `lfs_upload`, when there is no endpoint, check
  `git config --local --get filter.lfs.clean`: if it is not set, return None
  (push as on dev); if it is set, refuse. The returns are merged so the ruff
  PLR0911 ratchet does not regress.
- `apps/backend/core/worktree.py` `create_worktree`: call
  `enable_lfs_clean_filter(self.project_dir)` just before `git worktree add`.
- Tests:
  - `tests/test_lfs_push.py`: every no-endpoint origin pushes when no local
    filter is set and refuses when one is. Two real-git tests: a GitLab-origin
    LFS repo gets no filter, commits a raw blob and pushes with no LFS step; a
    github-https repo gets the local filter (smudge skipped, no pre-push hook),
    commits a pointer and uploads before the push. The `lfs_repo` fixture now
    also pins `XDG_CONFIG_HOME`, so a host global git-lfs config cannot leak in.
  - `tests/test_lfs_push_sites.py`: the packed-path GitLab case pushes without
    a local filter and refuses with one.
  - `tests/test_worktree.py`: `create_worktree` calls the helper on the project
    repo before the worktree exists.
- Check: `pytest tests/test_lfs_push.py tests/test_lfs_push_sites.py tests/test_worktree.py -q`
  plus the Tests list below.
