# Plan: model gateway image, built and signed in CI

## Approved decisions (copied from the spec, self-contained)

- **Owner decision:** the gateway is a second image built in AIFactory. It
  shares AIFactory's cosign signer (an accepted risk). It is an in-house,
  stdlib-only gateway; AIFactory's LiteLLM sub-chart is marked deprecated
  (docs and chart comments only, no behaviour change).
- **Image:** a `-gateway` tag variant of `ghcr.io/olafkfreund/aifactory`:
  `:sha-<short>-gateway`, `:latest-gateway`, `:v<X>-gateway`. The existing
  Kyverno glob and subject already cover it, so there is no gitops change.
- **Build:** a new `gateway` stage in the root `Dockerfile` (not the last
  stage). Its base is the same pinned Chainguard digest as `runtime`, with
  `apk upgrade` and the `SECURITY_REFRESH` cache-bust. It copies only
  `apps/model-gateway/gateway.py`, runs as `USER 65532`, and its entrypoint
  is `python /app/gateway.py`.
- **Gateway** (`apps/model-gateway/gateway.py`, stdlib
  `ThreadingHTTPServer`):
  - Env: `GATEWAY_UPSTREAM_URL` (http/https with a host, checked at
    startup), `GATEWAY_UPSTREAM_API_KEY` (optional), `GATEWAY_CLIENT_TOKEN`
    (required to forward), `GATEWAY_PORT` (default 8080).
  - `GET /healthz` returns 200 `{"status":"ok"}`.
  - `POST /v1/chat/completions` returns: 503 if the upstream or client token
    is unset; 401 on a bad or missing bearer (checked with
    `hmac.compare_digest`); 400 on a bad Content-Length; 413 over 10 MiB.
    Otherwise it forwards the body to `<upstream>/v1/chat/completions`,
    replacing the caller's Authorization with the upstream key, and returns
    the upstream status, Content-Type and body. It returns 502 when the
    upstream is unreachable.
  - Any other path returns 404.
  - Streaming is buffered (a shortcut comment). No routes, failover,
    telemetry or Plane B.
- **CI:**
  - The PR gate builds, smokes and Trivy-scans the gateway (Trivy v0.73.0,
    `HIGH,CRITICAL --ignore-unfixed --exit-code 1`).
  - `deploy.yml` builds, pushes, signs by digest, verifies and asserts the
    signature location in its own job, **not** in `pin.needs`.
  - `release.yml` builds and signs it with the other images, and
    `sbom-attest` attests it.

## Steps

   **`tests/model_gateway/__init__.py`, `tests/model_gateway/test_gateway.py`**
   (new).
   - Write the tests first, then the gateway per the decisions above.
   - Structure the gateway as `load_config(env) -> Config` (raises
     `ValueError` on a bad upstream URL), `make_server(config, host, port)`
     and `main()`.
   - The tests import it with
     `sys.path.insert(0, str(REPO_ROOT / "apps" / "model-gateway"))`. The

## Deviations during implementation

- Step 1: the upstream call goes through an opener that refuses redirects.
  A followed 3xx would carry `GATEWAY_UPSTREAM_API_KEY` to the redirect
  target, so the 3xx is returned to the caller instead, and a test pins it.
  Upstream 4xx/5xx responses are passed through with their status and body.
  The 413 test sends an oversize `Content-Length` header and no body.
- Step 2: the stage runs `RUN mkdir -m 0755 /app` and uses
  `COPY --chmod=0644`. A plain COPY left `/app` with no execute bit for the
  nonroot user (measured: `Permission denied` on start).
- Step 1 (review fix, lead's Opus review of #1912): `Handler.timeout =
  CLIENT_TIMEOUT` (30 s). Without it, a silent client (slowloris, before the
  401 check) or a short body under a large Content-Length held a handler
  thread forever. A test pins that a silent socket is closed. An upstream
  `HTTPError` whose body read fails now returns 502 instead of raising.
- CI scope: `apps/model-gateway` is added to `ci.yml`'s `ruff check` and to
  `cq-ratchet.yml`'s `ruff format --check`. `tests/test_ruff_scope_covers_the_tree.py`
  requires every Python directory to be in both, and the plan missed it.
