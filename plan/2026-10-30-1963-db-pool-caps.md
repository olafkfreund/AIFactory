# Plan: Cap AIFactory's DB connection pools

Approved: `server/db_pool.py` `pool_kwargs(url, prefix, size, overflow)`
(`{}` for SQLite; else `<prefix>_POOL_SIZE`, `<prefix>_MAX_OVERFLOW`,
`DB_POOL_TIMEOUT` default 10). Main engine `DB` 2 + 2; the tenant-teardown CronJob (`server/services/tenant_teardown.py:159`) `TEARDOWN_DB` 1 + 0.

## Steps

1. Add `apps/web-server/server/db_pool.py` (copy of PFactory's); pass
   `**pool_kwargs(DATABASE_URL, "DB", 2, 2)` to the main engine in
   `apps/web-server/server/database/engine.py`; pass `**pool_kwargs(database_url, "TEARDOWN_DB", 1, 0)` to the engine in `apps/web-server/server/services/tenant_teardown.py:159`.
   Document the env vars in `.env.example` and the env reference doc if the
   repo has one. → verify by ruff on the changed files
   Traps: do not import `server.database` from `db_pool.py` (it builds the engine).
2. Add a test for `pool_kwargs` (defaults, env override, SQLite `{}`, bad
   int raises) and that the engines get the capped pool on a
   `postgresql+asyncpg://` URL without connecting. → verify by pytest on it
   Traps: Codex's sandbox hangs on aiosqlite; the lead runs the suites.

3. (Lead review fix.) `apps/web-server/server/routes/project_authz.py`
   `authorize_project_for_user` (~:125-187): release the request session's
   pooled connection on the ALLOW path too. Move the `db.rollback()` (with
   `contextlib.suppress(Exception)`) to right after the `OrgMember` SELECT so
   both paths release it before the caller's push / `gh` / dispatch work and
   before the 403 audit write takes a second connection. In
   `apps/web-server/server/routes/merger.py` both handlers (~:112-133), roll
   back right after `_visible_project_ids` and before `refresh_all()` / the
   `to_thread` sweep. Test: after an allowed check the session is no longer in
   a transaction (`db.in_transaction()` is False).
   → verify by pytest on the new test and the existing project_authz/merger tests
   Traps: callers authorize before writing (existing #1919 comment); a 2 + 2
   pool exhausts at 4 concurrent idle-in-transaction requests.
   Deviation: the 403-path rollback stays where it was and the allow path gets
   its own rollback before `return org_id`. Moving one rollback above
   `check_project_access` expires the loaded `OrgMember` (lazy load in async)
   and needed `expunge`, which the route-test fakes lack.
4. (Lead review fix.) Regenerate the autonomy matrix with
   `scripts/gen_autonomy_matrix.py` (CI red). Correct the fleet table in
   `spec/` (worst case ~93 of 97 with PFactory at 2 pods; AIF CronJobs not
   deployed; TF verify engines per concurrent dispatch) and note
   factory-gitops#319 needs PFactory lowered to ~9/pod via env, or PgBouncer /
   a `max_connections` raise. → verify by the CI autonomy-matrix check
   Traps: none.
