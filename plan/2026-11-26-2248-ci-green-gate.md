# Plan: clear the `ci-green` gate from measured host CI

## Approved decisions (from the spec)

- PFactory contracts declare `deployment.system_gates: ["ci-green"]`. Today nothing satisfies the
  gate, so `decide_merge` returns `hold-blocking` for every planned task in a CI repo.
- Fix it in AIFactory only, in `apps/web-server/server/services/pr_endgame.py`. Make no change to
  PFactory or `merge_policy.py`.
- Add the constant `CI_GREEN_GATE = "ci-green"`.
- In `merge_disposition`:
  - Drop any caller-supplied `ci-green`, in any spelling (`strip().lower()`).
  - Add `ci-green` only when `merge_gate_signals(spec_dir, fetched=fetched)["host_ci_green"] is True`.
  - Pass the resulting set to `decide_merge`.
  - Nothing else is added to the satisfied gates.
- In `apply_path_risk_floor`, call `deployment_block_reasons(deployment, satisfied_gates=(CI_GREEN_GATE,))`.
  Every other floor reason stays.
- At PR open, the prospective `host_ci_green: True` counts as satisfying `ci-green`. That only arms
  the watcher. The merge gate checks measured CI on the head SHA, and the merge uses
  `--match-head-commit`.
