# Plan: clear the `ci-green` gate from measured host CI

## Approved decisions (from the spec)

- PFactory contracts declare `deployment.system_gates: ["ci-green"]`. Today nothing satisfies the
  gate, so `decide_merge` returns `hold-blocking` for every planned task in a CI repo.
- Fix it in AIFactory only, in `apps/web-server/server/services/pr_endgame.py`. Make no change to
  PFactory or `merge_policy.py`.
- Add the constant `CI_GREEN_GATE = "ci-green"`.
- `merge_disposition`, replacing the final call:
  ```python
  signals = merge_gate_signals(spec_dir, fetched=fetched)
  # Only the measured signal clears ci-green, never a caller-supplied name (any spelling).
  gates = {g for g in satisfied_gates if str(g).strip().lower() != CI_GREEN_GATE}
  if signals["host_ci_green"] is True:
      gates.add(CI_GREEN_GATE)
  return str(decide_merge(str(effective), **signals, deployment=deployment,
                          satisfied_gates=sorted(gates)))
  ```
  Nothing else is added. Every existing early hold stays as it is: import failure, host not
  isolated, `state == "hold"`, a verified contract without a signed tier, and an unreadable
  contract. High-risk and production deployments still hold inside `decide_merge`, and so does a
  persisted `reviewTier: blocking`.
- A direct caller can still satisfy `human-approval` alongside measured CI. On the live legacy path,
  `human-approval` still floors the tier to `blocking` before the PR opens.
- In `apply_path_risk_floor`, call `deployment_block_reasons(deployment, satisfied_gates=(CI_GREEN_GATE,))`.
  Every other floor reason stays.
- At PR open, the prospective `host_ci_green: True` counts as satisfying `ci-green`. That only arms
  the watcher. The merge gate checks measured CI on the head SHA, and the merge uses
  `--match-head-commit`.
