## Deviations (PR #1873 review, CHANGES_NEEDED)

- Hashed build backends: new `requirements-build.in` → `requirements-build.lock`
  (`uv pip compile --python-version 3.15 --generate-hashes`), the union of the
  `[build-system].requires` of lxml, xmlsec, real-ladybug, tree-sitter and pyyaml;
  xmlsec's `lxml==6.0.2` pin is left out. `py-build` now installs it with
  `--require-hashes`, then lxml alone from the main lock (`--no-binary`, hashed), then the
  full lock with `--require-hashes --no-build-isolation`, so xmlsec compiles against the
  lxml 6.1.1 it runs with. Build-only packages not in the runtime lock are uninstalled
  from the venv afterwards (installing them via `--target`+`PYTHONPATH` was rejected:
  pip then counts the shared `packaging` as installed and leaves it out of the venv).
  `deps-lock-drift` recompiles and diffs both locks.
- P0 build timeout: `tests/docker/helpers.py` `docker_build` default 600 s → 1800 s, and
  the `docker (P0 acceptance)` job 30 → 50 min so the job does not cut off the build first.
- The `libxmlsec1-openssl.so` link target is resolved at build time from
  `/usr/lib/libxmlsec1-openssl.so.*`, failing loudly if there is none.
- Separate apk resolution between `py-build` and `runtime` is accepted; noted in spec Risks.
