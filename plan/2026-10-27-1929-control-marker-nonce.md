# Plan: authenticate build stdout control markers

Approved decisions (from the spec):

- Per-task nonce `secrets.token_hex(16)`, generated by the control plane at
  spawn, stored in `AgentEmitMixin._task_marker_nonces[task_id]`, passed to
  the build as env `AIFACTORY_MARKER_NONCE`. Same channel (stdout / pod logs);
  no fd or file side channel.
- Wire format: `__EXEC_PHASE__:<nonce>:{json}`, `__USAGE__:<nonce>:{json}`,
  new `__RATE_LIMIT__:<nonce>:`. The control plane accepts a marker only with
  its known, non-empty nonce. Everything else is plain log text.
- Remove the `[PHASE_EVENT] k=v` and bare `{"phase"|"status":…}` parsers (no
  emitter exists).
- Remove free-text `_is_rate_limit_line`. Rate limit = authenticated
  `__RATE_LIMIT__` marker, emitted by the build from `core/client.py`
  `_patched_parse` when a parsed `AssistantMessage` has `error == "rate_limit"`.
- `AIFACTORY_MARKER_NONCE` joins `_AGENT_ENV_DENY_EXACT` so no `child_env()`
  passes it on and the SDK child gets it blanked. Control-plane spawn sites set
  it after `make_subprocess_env()`.
- Tolerant int conversion for `subtask_index`/`subtask_total`; `_process_output`
  survives any exception from one line.

## Deviations (recorded during implementation)

- Step 1: `_patched_parse` checks `getattr(msg, "error", None) == "rate_limit"`
  instead of `isinstance(AssistantMessage)`; only `AssistantMessage` has `error`.
- Step 2: an authenticated `__RATE_LIMIT__` line returns after the log emit and
  `log_writer.process_line` (both still run for every line).
- Step 3: `_marker_nonce_env` declared in the `TYPE_CHECKING` blocks of the
  kubejob and spec-creation mixins for mypy. Spec creation and the following
  build of the same `task_id` share one nonce.
- Step 4: `tests/conftest.py` mocks `claude_agent_sdk`, so the `_patched_parse`
  test runs the real patch function against a fake `parse_message`.
  `scripts/ratchet_lint.py` does not exist in this repo; not run.
