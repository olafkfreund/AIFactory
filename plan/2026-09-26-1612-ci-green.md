# Plan: replace the gated object store, name the DB driver, and fail loudly not fatally

Self-contained summary of the approved decisions.

## Approved decisions (carried from the spec)

- **MinIO is gated everywhere** (`quay.io/minio/minio` and `docker.io/minio/minio`
  both 401 anonymously; quay denies even the tag list). This is a substitution,
  not a registry change.
- **SeaweedFS replaces it**, chosen by experiment: both S3 integration tests pass
  against it locally in 1.11s, including
  `test_partial_upload_simulation_against_live_minio`, whose docstring says it
  defends the contract "against real S3 listing behavior" — the property a mock
  would most plausibly weaken.
- **Pin by digest**, so the next vendor policy change is a deliberate bump.
- **The start step must not be able to fail the job.** Its comment already claims
  an unavailable store makes the tests skip; `docker run` exits 125 and takes the
  job down instead. This has now caused two outages (`bitnami/minio` retiring
  mid-2026, then this).
- **A skip must be visible** — `::warning::`, not silence. The #597/#1496 rule.
- **`main` stays strict.** `ci.yml:5-7` triggers on `push` to `main`, so a blanket
  tolerance would let a release build silently lose its S3 coverage.
- **Name the DB driver** (`+psycopg2`) rather than inheriting SQLAlchemy's default,
  which changed between 2.0 (psycopg2, installed) and 2.1 (psycopg v3, not).
- **Do not pin SQLAlchemy.** Naming the driver removes the dependency on the
  default; a ceiling would add a stale pin without adding safety.
- **Define `sync_url()` once** in `tests/postgres/helpers.py`. Seven identical
  copies are why a one-line defect needed seven edits.

## Verified facts this plan relies on

- **Pin:** `chrislusf/seaweedfs:4.47@sha256:ce9e796f1fe6f06968f4c04bdaf8f678dad9c8acdfef3d244133d71bfa6bf882`
  (`4.47` and `latest` resolve to the same digest today; pin the release tag).
- **Start command:** `server -s3`, S3 on port **8333**, HTTP 200 after **5s**.
  `-dir` must name a directory that exists in the image — `-dir=/tmp/sw` fails
  `Check Meta Folder … no such file or directory` and the container exits 255.
  Omit `-dir`.
- **Bucket creation needs no `mc`:** `curl -X PUT http://localhost:8333/<bucket>`
  returned HTTP 200.
- **Credentials are accepted as supplied**; the tests pass their own, and
  `AIFACTORY_S3_ADDRESSING_STYLE=path` is already set by the fixture
  (`test_workspace_store_integration.py`), which SeaweedFS needs just as MinIO did.
- **The skip needs no conditional env — refinement on the spec.** The spec said
  the tests skip when `TEST_S3_ENDPOINT_URL` is *absent*. More precisely:
  `TEST_S3_URI_BASE` and `TEST_S3_ENDPOINT_URL` are hardcoded in the pytest step's
  `env:` block (`ci.yml:133-135`), so they are set even when the store failed to
  start; `_live_s3_reachable()` (`test_workspace_store_integration.py:58-75`) then
  socket-probes the endpoint, returns `False`, and the `live_store` fixture calls
  `pytest.skip(...)` (`:85-89`). So **only the `docker run` exit needs
  neutralising** — no env juggling. Simpler than the spec assumed, same outcome.
- **Stale comment to correct:** `ci.yml:129-132` describes a "services.minio
  container" with `MINIO_DEFAULT_BUCKETS`. There is no such service; it is the
  `docker run` step. The comment predates the move and misleads.

## Steps

1. `.github/workflows/ci.yml` — rename the step to name the store, swap the image
   for the pinned SeaweedFS digest, `server -s3`, port `8333`, and shorten the
   readiness loop to ~15s (it answers in 5). Replace the module docstring's `mc`
   recipe assumption with the `curl -X PUT` bucket creation. → verify by the step
   succeeding and the endpoint answering 200 in CI logs.

2. `.github/workflows/ci.yml` (same step) — make it non-fatal on a PR and strict
   on `main`: the `docker run` and readiness loop must not fail the step; on
   failure emit `::warning::` naming the docker exit and the container log tail,
   and continue. When `github.ref == 'refs/heads/main'`, exit non-zero instead.
   Keep the reasoning in a comment in the style of the bubblewrap step below it
   (`ci.yml:98-104`), which documents the #1365 pending-check failure mode.
   → verify by step 4 of Verification, not by reading it.

3. `.github/workflows/ci.yml:133-135` — point `TEST_S3_ENDPOINT_URL` at
   `http://localhost:8333`, set the credentials the SeaweedFS step accepts, and
   correct the stale `services.minio` / `MINIO_DEFAULT_BUCKETS` comment at
   `:129-132` to describe what actually happens. → verify by the two S3 tests
   passing in CI rather than skipping.

4. `tests/postgres/helpers.py` — add one typed `sync_url(url: str) -> str`
   returning `url.replace("+asyncpg", "+psycopg2")`, with a docstring saying why
   the driver is named: a bare `postgresql://` delegates the choice to
   SQLAlchemy, whose default moved from psycopg2 to psycopg v3 in 2.1 while only
   psycopg2-binary is installed (`tests/requirements-test.txt:37`). → verify by
   `postgresql+psycopg2://` resolving to the psycopg2 dialect (already confirmed
   locally).

5. `tests/postgres/` — replace all seven local `_sync_url()` definitions with an
   import of the helper, in `test_allowed_models_schema.py`,
   `test_audit_anchor_schema.py`, `test_audit_resource_id_width.py`,
   `test_external_identities.py`, `test_job_states_schema.py`,
   `test_per_tenant_audit_anchor_schema.py`, `test_tenant_states_schema.py`.
   → verify by `grep -rn "def _sync_url" tests/postgres/` returning nothing.

6. Commit, then run both halves of cq-ratchet on the changed Python (it diffs
   committed history). → verify by "0 regressed" from each.

7. Push, open the PR against `dev` linking all three artifacts. → verify by
   `backend (ruff + pytest)` and both `postgres (P1 acceptance)` jobs going green
   — they cannot today.

8. **Prove the tolerance** (spec verification 4, the item most likely to be
   skipped and the reason the fragility fix would otherwise be untested): on a
   scratch branch, break the image reference deliberately and confirm the step
   goes green, the `::warning::` is present, and the two S3 tests are reported
   **skipped** rather than passed. Delete the scratch branch afterwards; it is
   evidence, not a change. → verify by quoting the run.

## Rollback

`git revert <sha>`. CI configuration and test helpers only — no production code,
no runtime dependency, no schema, no deployment. Reverting restores the previous
behaviour exactly, which is to say it restores the outage; the revert would only
make sense alongside a different fix.

## Out of scope

- Pinning or capping SQLAlchemy (decided against; naming the driver is the fix).
- Migrating the production object store, which is unaffected — this is a test
  fixture only.
- The other two failing checks' root causes if they turn out to be independent:
  `secrets (P2 acceptance)` fails on all three PRs too and has not been
  diagnosed. If it is not one of these two causes, it gets its own issue rather
  than being folded in here.
