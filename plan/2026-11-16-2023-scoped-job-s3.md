# Plan: Per-dispatch scoped S3 credentials for agent Jobs

Approved spec decisions, carried over: MinIO STS AssumeRole with an inline
session policy; flag `AIFACTORY_SCOPED_JOB_S3` default off; caller creds
`S3_STS_ACCESS_KEY`/`S3_STS_SECRET_KEY` (control plane only, never forwarded);
Job env loses `S3_ACCESS_KEY`/`S3_SECRET_KEY` and gains `AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`; policy = Get/Put/PutObjectTagging
on `aifactory/<corr|_>/<id>/*` for each `(corr, id)`; build pairs
`(correlation_key, task_id)` and `(None, spec_id)`; spec pairs
`(None, <task_id>-spec-<fetch8>)` and `(None, fetch_id)`; build pairs also
`(None, "gate-<spec_id>")`; lifetime = max(build deadline, 7200s) + 1h; scoping runs after all
other env merges;  fail closed with
`BuildBackendUnavailableError`; `core/artifact_store.py` is not edited; the
shared-`spec_id` residual is documented, not fixed.

## Steps

1. `apps/web-server/server/services/job_s3_scope.py` (new) and
   `tests/test_job_s3_scope.py` (new; includes one test that patches `boto3.client`
   under `_assume` and checks endpoint, caller keys, policy and DurationSeconds,
   and one for `_lifetime` with a build deadline shorter than 7200) → verify by
   `python -m pytest tests/test_job_s3_scope.py -q`.
   Traps: vendored `artifact_store.py` stays byte-identical; import `ArtifactRef`
   lazily; ruff: plain names in parenthesised imports.
2. `build_backend.py` (after the `extra_env` merges, ~line 1394, before
   `build_run_py_job_manifest`): `await asyncio.to_thread(scope_job_s3, extra_env,
   [(correlation_key, task_id), (None, spec_id)])`. `spec_job_backend.py`
   (after `env.update({...})`, ~line 399): the same with
   `[(None, f"{task_id}-spec-{fetch_id[:8]}"), (None, fetch_id)]`. Add one test
   per site to `tests/test_build_backend_kubejob.py` and
   `tests/test_spec_job_backend.py` (flag on: manifest env has no `S3_SECRET_KEY`,
   has `AWS_SESSION_TOKEN`; STS patched) → verify by
   `python -m pytest tests/test_build_backend_kubejob.py tests/test_spec_job_backend.py tests/test_job_s3_scope.py -q`.
   Traps: spec job workspace is packed in `_prepare_spec_workspace` with the
   control-plane key, before the env swap: keep that order.
2b. `apps/backend/agents/gate_runner.py` `_STORE_ENV_VARS` (~line 449): add
   `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` so the nested
   gate Job's unpack initContainer authenticates with the scoped session. Test in
   `tests/test_gate_runner_nix.py`: `_store_env()` includes them when set →
   verify by `python -m pytest tests/test_gate_runner_nix.py -q`.
   Traps: `apps/backend` is shared with the Job image; the graphify cache is out of
   scope on purpose (spec Risks).
3. Docs: `docs/docs/environment-reference.md` (rows for the flag and the two STS
   vars) and `apps/web-server/.env.example` → verify by `git diff --stat`.
4. factory-gitops `apps/minio/manifests/manifests.yaml`: in the setup Job, when
   `STS_ACCESS_KEY` and `STS_SECRET_KEY` (optional keys of `minio-creds`) are
   set, create policy `aifactory-sts` (Get/Put/PutObjectTagging on
   `factory-artifacts/aifactory/*`) and the user, attach it; skip otherwise →
   verify by the repo's manifest-validate workflow commands and `yamllint`.
   Traps: image has no grep/sed; policy via heredoc; secret not echoed.
   Owner action (not done here): add `STS_ACCESS_KEY`/`STS_SECRET_KEY` to
   `minio-creds`, give the aifactory Deployment `S3_STS_ACCESS_KEY`/
   `S3_STS_SECRET_KEY`, set `AIFACTORY_SCOPED_JOB_S3=true`.

## Tests

`python -m pytest tests/test_job_s3_scope.py tests/test_build_backend_kubejob.py tests/test_spec_job_backend.py tests/test_agent_env_scrub.py -q` passes;

## Rollback

Unset `AIFACTORY_SCOPED_JOB_S3` (default): behaviour is the old bucket-wide key.
Revert the PR; the gitops user is inert without the flag.
