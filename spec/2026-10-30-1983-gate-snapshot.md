# Spec: read every run gate once, before the first agent session

## Design

### The snapshot

New module `apps/backend/run_gates.py` with one frozen dataclass. It extends
the #1940/#1945 run-start snapshot: `_approved_plan_snapshot` moves into it
from `agents/coder.py`, and `agents/coder.py` re-imports the name so
`tests/test_plan_seed.py` keeps working.

```python
@dataclass(frozen=True)
class RunGates:
    solo: bool
    requires_review: bool            # requires_review_before_coding(gate_dir), raw
    review: ReviewState              # loaded once; approval validity uses its hashes
    approved_plan: dict | None       # #1940 grant snapshot (unchanged semantics)
    metadata: TaskMetadataConfig     # load_task_metadata(gate_dir) or {}, deep-copied
    cli_model: str | None

    @classmethod
    def capture(cls, spec_dir, source_spec_dir, cli_model) -> "RunGates"
    def approval_valid(self, spec_dir) -> bool  # not requires_review or review.is_approval_valid(spec_dir)
    def model(self, phase) -> str               # get_phase_model(..., metadata=self.metadata)
    def thinking_budget(self, phase) -> int | None
```

`gate_dir = source_spec_dir or spec_dir`, the same rule as #1946, #1958 and
#1980. Approval validity keeps the stored hashes from the run start and still
hashes the live plan. So a plan the agent changed after approval still fails,
and a forged `review_state.json` is never read. Provider comes from the model
(`infer_provider_from_model`), so it is covered too. When `task_metadata.json`
is missing, `metadata` is `{}`, not `None`. Every `metadata and ...` check in
`phase_config` treats `{}` the same as `None`, and so does `contract_route`
(it checks `isinstance(dict)`, and an empty dict routes nothing). So a
metadata file the agent creates mid-run is never consulted.

### phase_config

`get_phase_model`, `_resolve_phase_model`, `get_phase_thinking` and
`get_phase_thinking_budget` gain a keyword-only
`metadata: TaskMetadataConfig | None = None`. `None` keeps today's behaviour
(`load_task_metadata(spec_dir)`). A dict is used as-is. Resolution precedence
and the registry assertion do not change. Model resolution stays lazy per
phase: computing every phase up front would raise `ModelNotApprovedError` in
registry `deny` mode for a phase the run never uses (for example QA on a solo
run).

### Where the snapshot is taken and read

| Site | Today | After |
|---|---|---|
| `cli/build_commands.py handle_build_command` | — | `RunGates.capture(spec_dir, source_spec_dir, model)` after workspace setup, immediately before the first `run_autonomous_agent` (no agent session has run yet) |
| `agents/coder.py run_autonomous_agent` ~212-218 | solo / require_review / approved_plan read live | from `gates` (new kwarg). `require_review = not gates.solo and gates.requires_review`. Falls back to `RunGates.capture(...)` at the same point when no gates are passed |
| `agents/coder.py` ~457-458 per-iteration model/thinking | `get_phase_model(spec_dir, …)` live, after the planner session | `gates.model(current_phase)`, `gates.thinking_budget(current_phase)` |
| `agents/parallel_integration.py` ~458-459 + plan seed | live model/thinking; `approved_plan` kwarg | `gates` kwarg replaces `approved_plan`; model, thinking and seed plan come from it (falls back to capture for direct callers and tests) |
| `qa/loop.py run_qa_validation_loop` ~232, 335, 541, 635 | live, after the coder | `gates` kwarg. QA and QA-fixer model/thinking from it. Falls back to a capture at loop start (the `--qa` Job, `cli/qa_commands.py`), which still protects the loop's own later rounds after its first QA/fixer session |
| `_approval_still_valid` (Ctrl+C resume, ~931-944) and `_handle_build_interrupt` | live `ReviewState.load` + `requires_review_before_coding` | `gates.approval_valid(spec_dir)`. The resumed agent gets the same `gates`, so its grant plan stays the run-start plan |

Not changed (read before any session in their process, or not a gate):
- the build pre-flight (`build_commands` ~315-445);
- the injection-scan approval escape hatch (`coder.py` ~1159, which runs
  before the first session);
- `cli/qa_commands.py` plan-command seeding (#1955, a separate `--qa` process,
  before its first session);
- `agents/planner.py run_followup_planner` (its own entry);
- `qa/correction.py _run_fixer_bg` (a separate correction path that reads
  before its own session);
- `agents/token_attribution.py` (an accounting label, not a gate);
- the `get_phase_model_betas` / `get_fast_mode` call sites (none in the build
  path).

QA plan-command seeding does not run in-process after the coder: the
in-process QA reuses the coder's in-memory profile, seeded from
`approved_plan`. Only the separate `--qa` Job seeds, and it does so on a fresh
unpack.

#1980's branch is not edited.

### client.py grant (not changed here)

Filed as #1985: reduce `<project>/.aifactory/**` to Read/Glob/Grep. The
legitimate writes there are:
- the task worktree itself (under `.aifactory/worktrees/tasks/<id>/`) and PR
  worktrees, which keep write access through their own `project_dir` /
  `spec_dir` grants;
- the spec files the prompts ask for, which go to the localized worktree spec
  dir and are synced back by the orchestrator (`sync_plan_to_source`,
  `agent_worktree_sync`).

No agent write to the source `.aifactory/` was found.

### Subprocess backend (read-only assessment)

There, `--project-dir` is the real persistent project, so the source spec dir
persists across runs and the same grant (plus Bash) lets the agent write it.

- **Closed:** every in-process read after a session. That covers the coder's
  later iterations, QA after the coder, the QA loop's later rounds, and the
  Ctrl+C resume.
- **Not closed:**
  - a write made in run N is read at the start of run N+1: the next build,
    the `--qa` run, or a retry. The snapshot then faithfully captures the
    forged value.
  - the control-plane approval record `task_control.json` (#1922) lives in
    the same spec dir.

  Closing these needs the gates computed by the control plane at dispatch and
  passed in (or stored outside the agent-writable tree), plus #1985 and the
  sandbox (#1932). Out of scope; noted on #1983 and #1985.

## Alternatives rejected

- **Freeze inside `load_task_metadata` (module-global cache).** It catches
  every caller at once, but it is hidden global state that tests and the
  control plane would also hit, and it cannot cover `ReviewState`.
- **Compute all phase models eagerly at capture.** In registry `deny` mode
  this raises for phases the run never uses.
- **Route each call through `source_spec_dir` only (#1980's approach).** The
  source copy is itself agent-writable in kubejob.
- **Control plane computes the gates at dispatch.** Stronger, and it would
  cover the subprocess cross-run case. But it changes the web-server and the
  Job contract. Kept as a follow-up.
- **Read-only grant in this PR.** The lead ruled it out (#1985). It is also
  not a boundary while Bash is unsandboxed.

## Risks

- Behaviour change only when files change mid-run. A human who edits
  `task_metadata.json` (model) during a build no longer affects that run; it
  takes effect on the next run. The previous per-iteration re-read was not a
  documented feature.
- Ctrl+C resume: a human approval given while the build is paused at the menu
  is no longer seen by that process. The resume refuses, and the operator
  re-runs. That is the safe direction.
- Textual conflicts with #1980 (see above).
- Per-subtask `model` from the plan (#376) still overrides the phase model.
  The plan is human-approved when review is required. Otherwise it is an
  agent-written file. Unchanged here; noted on #1983.

## Verification

- Regression test `tests/test_run_gates_snapshot.py`, which must fail on dev.
  It starts a run with a source spec dir that requires review, has a valid
  approval, and has `phaseModels.qa` sonnet / `phaseThinking.qa` high. A fake
  coder session (patched `run_autonomous_agent` side effect) writes into the
  source spec dir a forged `review_state.json` (approved, hashes of the
  current plan), `task_metadata.json` with `soloMode: true`,
  `pinnedModel: haiku` and `thinkingLevel: none`, then changes the plan. The
  test asserts:
  - the QA model and thinking budget that `run_qa_validation_loop` uses are
    unchanged (sonnet / high);
  - `gates.approval_valid` and `_approval_still_valid` refuse after the plan
    change, despite the forged review state;
  - `gates.solo` is unchanged.
- Unit tests for `RunGates.capture` and for `metadata={}` with a forged
  file present.
- Existing suites: `tests/test_plan_seed.py`,
  `tests/test_build_interrupt_resume_approval.py`,
  `tests/test_plan_review_gate_snapshot.py`, `tests/test_solo_mode.py`,
  `apps/backend/test_routing_policy.py`, and the parallel tests.
- ruff 0.14.10 and the CI mypy ratchet on changed files.
