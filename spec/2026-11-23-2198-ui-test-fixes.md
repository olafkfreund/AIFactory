# Spec: AIFactory UI test fixes

## Design

- **B1.** `GET /env` (`routes/context.py:440-443`) moves from `admin` to
  `viewer`. The route takes the `ProjectAccess` from `require_project_role`
  through a dependency, so the effective role includes the token scope
  ceiling. The `ProjectAccessChecker` route-table contract is kept.
  - Below admin, the response is built from an **explicit allowlist**:
    `gitProvider`, `gitRepo`, `githubRepo`, `gitOrg`, `gitProject`,
    `gitBaseUrl` with any URL userinfo stripped, the `*Set` / `*Enabled`
    booleans (plus `githubTokenSet` and a new `graphitiKeysSet` per key),
    `mcpServers` booleans and `agentMcpOverrides`.
  - `customMcpServers` entries are reduced to metadata: name, type, and
    command or URL host without userinfo. No headers, env or args.
  - Nothing else is returned: no `gitToken`, no Graphiti API keys.
  - Admin and owner get the full payload. PATCH stays `admin`.
- **B3.** The owner's 403 comes from a startup-backfilled default-team
  `TeamMembership` row with `provenance="manual"` and role `member`, which
  OIDC sync never touches. Login already syncs `OrgMember.role` and SSO
  team rows (`oidc/provisioning.py:150-159,192-194`). Fixes:
  - `_role_for_userinfo` (`:56-58`) picks the **highest** mapped role over
    all of the user's groups, not the first match;
  - `User.role` is synced on login like `OrgMember.role`, so the JWT claim
    is current;
  - startup-backfilled rows are marked `provenance="backfill"` (migration
    plus backfill code at `database/engine.py:398`), and OIDC sync treats
    `backfill` like `sso`;
  - truly `manual` rows are never touched;
  - every role change writes `log_audit_event` (`services/audit_service.py:182`).

  IdP group removal still lowers the role on the next fresh login, as today.
  The gitops step sets `oidc.groupToRole` for the owner's Keycloak group,
  which the owner names or creates. Rollback: the image revert plus a
  migration downgrade that restores `manual`.
- **B4.** `api-adapter.ts:675,943`: the version comes from
  `/api/health` (`version`), cached for the session, and "unknown" on
  error.
- **B6.** The Ollama and openai-compat model fetches
  (`GeneralSettings.tsx`, `AgentProfileSettings.tsx`,
  `AgentProfileSelector.tsx`) run only when that provider is selected or has
  a base URL set.
- **B10.** A new `GET /api/projects/default-location` returns the server
  workspace root (`project_workspace_service.workspace_root()`) when it sits
  inside the browse roots, else null. `AddProjectModal.tsx` then:
  - defaults to `clone`;
  - resets its state on open only (the effect no longer depends on
    `scanProjects`);
  - scans only when the user picks Local, starting from the server default.
- **B11.** `activeStage()` in `PipelineBoard.tsx:71-78` returns null for
  done tasks, which covers every caller. `PipelineHeader.tsx` `derive()`
  (`:46-60`) skips done tasks entirely.
- **B12.** `AgentProfileSettings.tsx:47,124`: separate the saved choice
  from the effective one. An unset profile shows "Auto (default)", is not
  highlighted as chosen, and keeps its phase controls. Add the labels to the
  `en` and `fr` `settings.json`.
- **B4 detail.** One cached in-flight promise serves `getAppVersion` and
  `getDebugInfo`. A failure yields "unknown" and is retried on the next
  open.
- **B6 detail.** Only the live probes are gated: `fetchOllamaModels` runs
  only when the provider is Ollama or an `ollamaBaseUrl` is set (and passes
  that URL). `/settings/openai-compat/models` runs only with
  `llmOpenaiBaseUrl` set. Saved-endpoint discovery (`/llm-endpoints`) stays
  as it is. `AgentProfileSelector` reads the settings store for the gate.
- **B17.**
  - **Chat history:** `ChatHistorySidebar.tsx:100-135` filters to
    `messageCount > 0 || id === currentSessionId` before grouping and the
    empty state. The insights store bumps a session's `messageCount` when a
    message is added (`insights-store.ts:324-333`), so switching away never
    hides a real chat.
  - **Index:** `ProjectIndexTab.tsx:112-116` and `ServiceCard.tsx:38-42,71-76`
    show paths relative to `project_root`, and the root itself as the
    project name.

## Alternatives rejected

- **Lowering the GET env role without redaction:** it leaks `gitToken`.
- **Giving every SSO user admin:** too broad. The group mapping is explicit.

## Risks

- B1 redaction must cover every secret field. Its test asserts that a
  member response holds no token values.
- B3 must not downgrade a manually granted admin.

## Verification

- Unit and route tests for B1 (viewer gets redacted, admin gets full,
  PATCH still admin), B3 (mapping upgrades, never downgrades) and B11 (done
  task does not light Review).
- vitest for B4, B6, B10 and B12.
- CI.
- After release, a browser re-test:
  - the MCP view and Project General without 403;
  - Settings shows the right version;
  - no 409s in the network log;
  - Add Project opens on Git URL;
  - the board's Review circle is not lit;
  - chat history has no empty sessions.
