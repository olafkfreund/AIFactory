# Spec: run the target repo's lint as a trailing gate (opt-in)

Line numbers are at `4638e87d` (origin/dev, 2026-10-17). Paths are under
`apps/backend/` unless stated.

## Design

One env flag, `AIFACTORY_REPO_LINT_GATE` (`1`/`true`/`yes` = on, anything
else = off, default off). With it off, nothing changes. With it on:

### 1. `agents/gate_runner.py`: curated lint gates

- `_LINT_COMMANDS: dict[str, list[str]]`, the only lint commands that ever
  run:
  - `flake8` -> `["flake8"]`
  - `ktlint` -> `["ktlint"]` (lints `**/*.kt*` under cwd)
  - `ruff` -> `["ruff", "check", "."]`
- `repo_lint_enabled(env=os.environ) -> bool` reads the flag.
- `lint_gates(linters: list[str]) -> list[Gate]`: `[]` when the flag is
  off; otherwise one `Gate(name=tool, command=_LINT_COMMANDS[tool],
  skip_code=127)` per name in `linters` that has a curated command, in input
  order. `skip_code=127` makes a missing tool `skipped` on runners that pass
  the shell's exit code through (host via `nix develop ... bash -c`, docker
  already maps 127).
- Not curated, so they stay `<name>: skipped` exactly as #1627 records
  them: `eslint` (the npm `lint` gate covers it), `spotless` and `detekt`
  (Gradle plugins, fetch at run time, no network in the sandbox),
  `golangci-lint` (needs module downloads), `swiftlint` (no Linux nixpkgs
  build).

### 2. `agents/coder.py`: `_run_trailing_gates_if_build_complete`

- Move the `ci_linters` import (:1353) up and compute `linters =
  ci_linters(gate_dir)` once, after the route gate (:1337-1339).
- `gates.extend(lint_gates(linters))` before `if not gates:` (:1341), so a
  repo whose only gate is its linter still gets a run. Annotate the
  `if not gates:` branch: with the flag on, lint gates are counted here.
- The #1627 skipped-record loop (:1356-1360) reuses `linters` and treats a
  name as covered when *any* result carries it (`ran = {r.name for r in
  results}`), so a lint gate that was itself skipped is not recorded twice.
- A lint gate that fails is in `failing_gates`, so it lands in
  `GATE_FAILURES.md` with its output tail and the fix loop gets it. That is
  the answer to "should a lint that ran and failed block": yes, when the
  operator turned the flag on.

### 3. `prompts_pkg/prompt_generator.py`: planning sees the repo's lint

In `generate_planner_prompt` (:236), before the untrusted boundary
(:295): when `repo_lint_enabled()` and `ci_linters(project_dir)` is
non-empty, append a short `## REPO LINT` section naming those allowlisted
linters and saying the trailing gate runs them after the last subtask, so
subtasks should keep the code clean for them. Only constants from
`CI_LINTERS` reach the prompt; CI text never does.

### 4. `analysis/ci_discovery.py`: cap workflow files (#1627 review LOW)

`ci_linters` (:458) returns `[]` when `.github/workflows` holds more than
`_MAX_WORKFLOW_FILES = 64` `*.yml`/`*.yaml` files. It now runs twice per
build (planning and gates), on agent-writable files.

### 5. Wiring and docs

- `apps/web-server/server/services/build_backend.py`
  `_PASSTHROUGH_BUILD_ENV` (:253): forward `AIFACTORY_REPO_LINT_GATE`, or a
  dispatched build Job never sees the flag (#1796 pattern).
- `docs/docs/environment-reference.md` (:381 table): one row.
- `CHANGELOG.md` `[Unreleased]`: one entry.
- Regenerate the autonomy matrix only if `scripts/gen_autonomy_matrix.py
  --check` fails.

### Answers to the intent's open questions

1. Lint that ran and failed blocks (goes to the fix loop) when the flag is on.
2. Curated table in `gate_runner`, not a descriptor `lint` lane:
   `KNOWN_LANES` and the YAMLs are vendored from the Factory hub under a
   drift gate. A follow-up can move the table into descriptors.
3. No nix provisioning or version capture now; a missing tool is `skipped`.

## Alternatives rejected

- **Run the CI step text.** Untrusted command text; refused by the intent.
- **Descriptor `lint` lane.** Cross-repo schema change (hub drift gate).
- **On by default.** Repos with existing lint debt, or a nix/kube substrate
  without the linter, would fail builds that pass today.
- **Warn-only lint gate.** Already what #1627 gives (`skipped`); does not
  meet outcome "do not report complete while lint fails".

## Risks

- **kubejob / nixjob runners** report a failed Job as exit 1, not 127
  (`gate_runner.py:375-401`, :534-540), so with the flag on a linter missing
  from the image or flake reads as *failed*, not skipped. Same contract the
  existing gates have there ("a per-task image is expected to carry its own
  toolchain"). Operators enable the flag only where the linter is present.
- **Version drift**: a host/nix linter can differ from CI's pinned version
  and disagree with CI. Opt-in limits the blast radius.
- **ruff config**: `ruff check .` uses the repo's own config; with none, it
  applies ruff defaults, which CI would also apply.
