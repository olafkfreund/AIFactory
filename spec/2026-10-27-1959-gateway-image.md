# Spec: model gateway image, built and signed in CI

## Design

### Image identity: a `-gateway` variant of `ghcr.io/olafkfreund/aifactory`

Tags `:sha-<short>-gateway`, `:latest-gateway`, `:v<X.Y.Z>-gateway`,
the same way the `-nix` and `-rmux` variants are named. The existing Kyverno
rule (`ghcr.io/olafkfreund/aifactory:*`, subject
`AIFactory/.github/workflows/(deploy|release|build-nix).yml@refs/heads/main`)
already covers these tags, so admission verifies the gateway with **no
factory-gitops change**. The GHCR package is already anonymously readable,
which Kyverno depends on. That removes remaining slice 1 from the intent.

### Build: a `gateway` stage in the root `Dockerfile`

```
FROM cgr.dev/chainguard/python:latest-dev@sha256:<same digest as runtime> AS gateway
ARG SECURITY_REFRESH=0
RUN apk upgrade --no-cache   (same daily cache-bust as runtime)
COPY apps/model-gateway/gateway.py /app/gateway.py
USER 65532
EXPOSE 8080
ENTRYPOINT ["python", "/app/gateway.py"]
```

It sits in the same file as the other stages so Dependabot (`directory: "/"`)
and `base-image-pin-liveness.yml` keep its base digest current with no config
change, and one digest bump moves every stage together. It is **not** the
last stage, so any untargeted `docker build` still produces `build-runtime`
as today. It copies one file, so nothing from the app image reaches it.

### Gateway: `apps/model-gateway/gateway.py`, stdlib only

`http.server.ThreadingHTTPServer`, configured from env:

| Env | Meaning |
|---|---|
| `GATEWAY_UPSTREAM_URL` | OpenAI-compatible base URL, e.g. `https://ollama.com`. Must be `http`/`https` with a host, checked at startup. |
| `GATEWAY_UPSTREAM_API_KEY` | Optional. Sent upstream as `Authorization: Bearer`. The only provider credential, held only here. |
| `GATEWAY_CLIENT_TOKEN` | Required to forward. Callers must present `Authorization: Bearer <token>`, compared with `hmac.compare_digest`. |
| `GATEWAY_PORT` | Default `8080`. |

Endpoints:

- `GET /healthz` → `200 {"status":"ok"}`. Always answers, so liveness can tell
  "dead" from "correctly refusing".
- `POST /v1/chat/completions`:
  - `503` if upstream or client token is unset. Fails closed: an
    unconfigured gateway is never an open relay.
  - `401` on a missing or wrong caller token.
  - `413` if the body is over 10 MiB; `400` on a bad `Content-Length`.
  - Otherwise forwards the body to `<upstream>/v1/chat/completions`. The
    caller's `Authorization` is replaced, never passed through. Returns the
    upstream status, `Content-Type` and body. Upstream unreachable → `502`.
- Anything else → `404`.

This matches the OpenAI path that the existing client seam
(`providers/_gateway.py`, `LITELLM_GATEWAY_URL`) already targets, so pointing
that seam at the gateway later needs no client change.

Not in this slice, named so it is not mistaken for done: streaming
(`stream: true` is buffered), routes and catalog, failover, quota, telemetry,
Plane B. They are later slices in the intent.

### CI

- **`image-build.yml` (PR gate):** a second job, `gateway`, with no `if:`. It
  builds `target: gateway` with `load: true`, runs the container and asserts
  `/healthz` returns 200 and an unauthenticated `POST` returns 503. It then
  runs Trivy pinned at `v0.73.0` via the same SHA-pinned
  `aquasecurity/setup-trivy`, with
  `--severity HIGH,CRITICAL --ignore-unfixed --exit-code 1`, the P0.8 policy.
- **`deploy.yml`:** a `build-gateway` job, gated on the same
  `needs.changes.outputs.deploy == 'true'`. It builds `target: gateway`,
  pushes `:sha-<short>-gateway` and `:latest-gateway`, runs
  `cosign sign --yes` by digest, the `cosign verify` self-test and
  `assert-signature-location.sh`, the same steps `build-push` runs. It is
  **not** in `pin.needs`: nothing pins or deploys the gateway, and a gateway
  failure cannot block or half-pin an app deploy.
- **`release.yml`:** a `build_gateway` step (`:v<X>-gateway`,
  `:latest-gateway`, `provenance: mode=max`, `sbom: true`). It is signed
  and location-asserted alongside the other three, and exposed as job output
  `gateway`. `sbom-attest` resolves, scans and attests it like the others,
  uploads `sbom-gateway.*`, and the dispatch `images` input accepts `gateway`.

### Tests: `tests/model_gateway/test_gateway.py`

A real gateway on port 0 in a thread, against a fake upstream
`http.server` that records the request. The cases:

- healthz is 200;
- 503 with no client token configured;
- 401 with a wrong caller token;
- 413 on an oversized body;
- a forwarded request reaches `/v1/chat/completions` with the upstream key
  and **not** the caller's token, and its status and body come back;
- 502 when the upstream is down;
- the startup check rejects a `file://` upstream.

These run in the existing `pytest tests/` CI step.

### LiteLLM deprecation (docs and chart only)

A `DEPRECATED (Factory#1959)` note on the `litellm-helm` dependency in
`charts/aifactory/Chart.yaml`, on the `litellm:` block in `values.yaml`, and
an admonition at the top of `docs/docs/concepts/litellm-gateway.md`. Each
points to the in-house gateway. No behaviour change. Removal is a later slice.

## Alternatives rejected

- **A separate `ghcr.io/olafkfreund/model-gateway` package.** A new GHCR
  package needs its visibility and repo linkage set by hand. Kyverno reads
  GHCR anonymously, and the image glob would need a factory-gitops change,
  which is out of bounds this wave. The tag-variant buys the same verification
  for free.
- **A separate `apps/model-gateway/Dockerfile`.** Dependabot watches `/` only
  and the pin-liveness workflow names the root file. A second file needs two
  config changes and lets its digest drift from the others.
- **Signing in a new workflow.** The Kyverno subject only admits `deploy`,
  `release` and `build-nix`. A new workflow name would sign images that
  admission rejects.
- **Using `factory_common` or `requests`.** Neither is in a one-file stdlib
  image. The upstream is operator config, not caller input, so it is validated
  once at startup rather than per request.
- **Upstream LiteLLM.** Rejected by the epic and the owner (third-party signer,
  unverified at admission).

## Risks

- **Shared signer** (accepted by the owner, see the intent).
- **`kustomize edit set image ghcr.io/olafkfreund/aifactory=...` in
  `deploy.yml`'s `pin` job** rewrites every reference to that image name in
  the AIFactory kustomization. The gateway has none today. The deploy slice
  must put the gateway in its own Argo app, or the next AIFactory deploy
  would repoint it at the app image. Recorded for that slice.
- **A Trivy HIGH in the base** turns the new PR job red. It shares the
  runtime's digest and upgrade, which pass P0.8 today, so it fails only when
  the app image does too.
- **CI minutes:** one extra small build per PR and per deploy, plus one extra
  syft scan per release.
- **Signing only runs on `main`**, so this PR cannot show a signature. The
  first one appears on the next release.
