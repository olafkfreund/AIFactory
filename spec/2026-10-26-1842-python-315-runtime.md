# Spec: move the runtime image to CPython 3.15

## Design

Chosen design, as decided in the 2026-10-24 team check on #1842:

1. **Base digest.** Both `FROM cgr.dev/chainguard/python:latest-dev@sha256:…`
   lines move to the current 3.15 digest.
2. **New `py-build` stage** in `Dockerfile`, from the same base digest. It runs
   `apk add build-base cmake xmlsec-dev xmlsec-openssl libxml2-dev libxslt-dev pkgconf openssl-dev libtool`,
   links `/usr/lib/libxmlsec1-openssl.so` to the versioned soname (the `-dev`
   package does not ship it, and xmlsec links `-lxmlsec1-openssl`), creates the
   venv at `/home/projects/MagesticAI/.venv`, and runs
   `CXXFLAGS="-include cstdint" pip install --require-hashes --no-binary lxml,xmlsec,real-ladybug -r requirements.lock`.
   `-include cstdint` works around a missing include in real-ladybug's vendored
   thrift headers under GCC 16. lxml is built from source so it links the same
   system libxml2 as xmlsec; a wheel bundles its own and `import xmlsec` then fails
   with "lxml & xmlsec libxml2 library version mismatch". pip is uninstalled from
   the venv in the same layer, as today.
3. **Runtime stage** replaces `python3 -m venv` and `pip install` with
   `COPY --from=py-build --chown=nonroot:nonroot` of the venv, and adds the runtime
   libraries `xmlsec xmlsec-openssl libxml2-16 libxslt`. Compilers, cmake and
   headers stay in `py-build`.
4. **Lock.** `requirements.lock` is recompiled with `--python-version 3.15`
   (header and `deps-lock-drift` job in `.github/workflows/ci.yml` alike), taking
   asyncpg 0.32.0, google-crc32c 1.9.0, grpcio 1.84.x, httptools 0.9.0,
   jiter ≥0.17, markupsafe 3.0.4, pydantic 2.14.0 + pydantic-core 2.50.0,
   rapidfuzz 3.14.6, uvloop 0.23.0. lxml stays 6.1.1. tree-sitter 0.25.2 and pyyaml
   6.0.3 build from their sdists, whose hashes are already locked.
5. **`apk del py3.14-pip py3.14-pip-base`** becomes the `py3.15-*` names.
6. **Dependabot:** remove the `*chainguard/python` ignore.

Existing apk CVE floors and the vendored-npm overlay pins are kept unchanged.

## Alternatives rejected

- **`--no-binary` in the `uv pip compile` command** (suggested in the probe
  outline). Not needed: uv already writes the sdist hash of every locked version,
  verified for lxml, xmlsec and real-ladybug. Changing the compile flags would
  only restrict the lock and widen the drift-job diff.
- **Building in the runtime stage and `apk del`-ing the build deps.** Leaves the
  layers in the image history and couples the build to the nonroot venv layer.
- **Ship 3.15 with SAML gated off.** The fallback in the probe; a product
  decision, not needed because xmlsec builds.
- **Bumping ruff `target-version` (py311) and the CI `setup-python` versions
  (3.11/3.12).** Those declare the oldest supported interpreter and the test
  runner, not the image runtime; only runtime pins move. `nix_provisioner.py`'s
  version map lists interpreters agents may request and is unchanged.

## Risks

- xmlsec now links the system libxmlsec 1.3.12 (older than the 1.3.17 the wheel
  bundled), so its CVEs come through Wolfi and Trivy.
- Source builds (lxml, real-ladybug C++, tree-sitter) slow the image build; the
  CI build has an 1800 s P0 timeout in a 50-minute job. `py-build` caches as a layer.
- pydantic 2.14 is the widest behavioural change; the backend test suite covers it.
- `py-build` and `runtime` resolve apk packages separately, so their xmlsec/libxml2
  revisions can differ by a rebuild. Accepted: the venv links sonames
  (`libxml2.so.16`, `libxmlsec1*.so.10312`), and a soname change fails the import smoke.
- `-include cstdint` is a workaround to drop once real-ladybug fixes the header.

## Verification

- `docker build --target runtime` succeeds locally.
- In the image: `python -V` is 3.15.x; `pip check` in a throwaway copy is clean;
  `import lxml, xmlsec, real_ladybug, pydantic, asyncpg, uvloop, grpc, tree_sitter, yaml`
  succeed; `onelogin.saml2` imports; an xmlsec sign/verify round-trip passes.
- The container starts with its default CMD and `curl /api/health` returns 200.
- CI green, including `deps-lock-drift` and the Trivy P0 docker gate.
