# Spec: Cap AIFactory's DB connection pools

## Design

Same pattern as PFactory#964: new dependency-free module
`apps/web-server/server/db_pool.py` with
`pool_kwargs(url, prefix, size, overflow) -> dict[str, int]`: `{}` for SQLite
URLs; else `pool_size` from `<prefix>_POOL_SIZE`, `max_overflow` from
`<prefix>_MAX_OVERFLOW`, `pool_timeout` from `DB_POOL_TIMEOUT` (default 10).

- Main engine `apps/web-server/server/database/engine.py`: prefix `DB`, 2 + 2.
- the tenant-teardown CronJob (`server/services/tenant_teardown.py:159`): prefix `TEARDOWN_DB`, 1 + 0 (it opens a single session).

### Shared Postgres budget (corrected after the lead's review)

`max_connections` 100, 3 reserved: **97 usable**. Measured 2026-10-30: AIFactory 3 (1 pod), PFactory 7 (2 pods), TFactory 1 (1 pod).

| Service | Per pod before | KEDA max | Per pod capped | Fleet capped (worst case) |
| --- | --- | --- | --- | --- |
| PFactory (PFactory#964) | 38 | 2 | 19 | 38 |
| AIFactory main engine | 15 | 6 | 2 + 2 = 4 | 24 |
| AIFactory CronJobs (tenant teardown) | 15 | – | 1 + 0 | 0 (not deployed) |
| TFactory main engine | 15 | 4 | 2 + 2 = 4 | 16 |
| TFactory verify-dispatch engines | 15 each | 4 | 1 + 0 **per concurrent dispatch** | ~15 (scales with concurrent dispatches) |
| **Total** | | | | **~93 of 97** |

Thin headroom. factory-gitops#319 (PFactory at 4 pods) would reach **~131**: before it leaves draft, lower PFactory's caps to ~9/pod via env (e.g. `DB_POOL_SIZE=2 DB_MAX_OVERFLOW=1 JOBSTORE_DB_POOL_SIZE=1 JOBSTORE_DB_MAX_OVERFLOW=0 PLAN_SESSION_DB_POOL_SIZE=1 PLAN_SESSION_DB_MAX_OVERFLOW=0` → 3 + 1 + 1 + relay 3 = 8), or add PgBouncer / raise `max_connections`.

Accepted, uncapped: the one-off crypto CLI engines (AIFactory `server/crypto/__main__.py:108`, TFactory `server/crypto/__main__.py:122`): operator-run, single process, short-lived.

## Alternatives rejected

- Raise `max_connections` / add PgBouncer in factory-gitops: out of this
  lane's scope; may still be needed for factory-gitops#319.
- A shared helper in factory-common: needs a vendored-drift release in every
  repo for a 10-line function.

## Risks

Too-small pools give fast `TimeoutError`s under bursts instead of waits;
env overrides raise them without a release.

## Verification

Unit tests for `pool_kwargs` and the engines' pool sizes; the repo's test
suite and lint ratchet; CI green.
