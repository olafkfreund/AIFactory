# Spec: Enable the new Claude, Codex and Antigravity models

## Design

1. `apps/backend/phase_config.py` `MODEL_ID_MAP`: `opus` -> claude-opus-5-5 (unchanged), `sonnet` -> claude-sonnet-5-5, `haiku` -> claude-haiku-5-5, new `fable` -> claude-fable-5-2. Legacy pins kept: `opus-4.8`, `opus-4.7`, `opus-1m`, `opus-4.5`, `sonnet-4.6`, plus new `sonnet-5` (claude-sonnet-5) and `haiku-4.5` (claude-haiku-4-5-20251001). `ADAPTIVE_THINKING_MODELS` gains claude-sonnet-5-5, claude-haiku-5-5, claude-fable-5-2. Provider detection already routes `gpt-*` to codex and `gemini*` to antigravity; a test pins gpt-6.* and gemini-4-*.
2. Shorthand-to-id copies follow: `core/budget_enforcement.py` `_SHORTHAND_TO_CATALOG`, `core/model_config.py` `DEFAULT_UTILITY_MODEL` (haiku-5-5), the hard-coded haiku in `core/workspace/merge.py`.
3. Price/capability tables, from the claude-api skill (2026-11-03 cache): fable-5-2 $8/$40 (cache read $0.20), opus-5-5 $4/$20 (cache read $0.20), sonnet-5-5 $2/$10 (cache read $0.10), haiku-5-5 $0.10/$0.50 up to 100K prompt, all 1M context. Corrections of rows that were wrong: opus-5-5 (was provisional $5/$25), sonnet-5 ($2/$10, was $3/$15), sonnet-4-6 context 1M, haiku-4-5 $1/$5. Cache creation uses the existing 1.25x convention. Touched: `core/model-catalog.json`, `core/enforcement.py` `_CLAUDE_PRICING`, `model_registry.py` `DEFAULT_REGISTRY` (haiku-5-5 approved for `qa` only, like haiku 4.5), `core/cache.py` `_MIN_CACHE_TOKENS` (512 for the 5.x ids). Haiku 5.5 cache rates are not published in the skill: derived 0.1x / 1.25x, commented as derived. Catalog entries for gpt-6.* and gemini-4-*/3.8 are added with `price.mode` "subscription" (codex) and no price fields (gemini), with a comment, never an invented figure.
4. UI catalog `apps/frontend-web/src/shared/constants/models.ts` (ALL_AVAILABLE_MODELS, AVAILABLE_MODELS, PROVIDER_MODELS claude/codex/gemini, frontend MODEL_ID_MAP) and the web-server `insights_providers/{claude,codex,antigravity}_provider.py`: new models first, old ones kept below under their old ids. Gemini 4 ids carry the `-medium` suffix observed in the local agy config; gemini-3.8-flash is listed low/medium/high. `tests/test_gemini_model_ids_are_usable.py` widens its guard to 3.8 and 4 (effort suffix required).
5. Tests: update pins to old ids (`test_latest_models.py`, `test_routing_policy.py`, others the suite shows failing); add a test that the shorthands map to the new ids, old aliases still resolve, `fable` resolves, and gpt-6.x / gemini-4-* route to codex / antigravity.

## Alternatives rejected

- Rename old shorthands only in the UI: the backend would keep running old Sonnet/Haiku. Rejected.
- Change codex/antigravity `_DEFAULT_MODEL`: the in-image CLIs (gemini-cli alias, Dockerfile:416) are not proven to serve gemini-4-*; selecting per phase is enough and risk-free. Rejected for now.
- Drop old ids: breaks saved settings and running tasks. Rejected.
- Edit `scripts/cost_router_core.py`-style self-test fixtures: they are synthetic and independent of real ids. Left alone.

## Risks

- Users with `sonnet`/`haiku` saved move to Sonnet 5.5 / Haiku 5.5: cost is lower, behavior differs (Haiku 5.5 rejects budget_tokens; the existing code path already sends none for non-Opus ids).
- Haiku 5.5 cache numbers are derived; flagged in code.
- The bundled Claude Code CLI in the pod logs `unrecognized_model` for haiku-5-5 and fable-5-2 but still answers; fable is opt-in only.

## Verification

- Pod proof (done 2026-11-19): Agent SDK query to claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5, claude-fable-5-2 each returned "OK".
- pytest on the touched tests; ruff; frontend typecheck/lint/vitest for models.ts users; the ratchet scripts the repo CI runs.
