# Spec: Dispatch grace for the stranded-build reaper

## Design

The admission row (`running`, pending ref) is written before populate/pack, so it is the in-flight marker. In `reap_vanished_jobs`, when the ref is reconstructed and the Job is `gone`, skip the row while `now - updated_at < _DISPATCH_GRACE_SECONDS` (300 s). Live Jobs, succeeded and failed Jobs are unaffected: only the "gone" verdict is deferred. A crashed dispatch is reaped on a later tick once the grace passes.

## Alternatives rejected

- A separate in-memory in-flight set: lost on restart and not shared across replicas.
- A new DB column: schema change for no gain over `updated_at`.
- Grace for every outcome: would delay #857 verdicts for no reason.

## Risks

A crashed dispatch holds its slot 5 min longer. Codex found `_to_epoch` read naive UTC `updated_at` as local time (wrong off UTC); fixed by treating naive datetimes as UTC, which also corrects the existing deadline path.
