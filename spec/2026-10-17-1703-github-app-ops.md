# Spec: GitHub App operations: clone PATs, Copilot reviews, registration

## Decisions (user, 2026-10-17)

1. #1703: **accept and document** the stored clone PAT. Using the App token
   for clones (`kind="github_app"`) rides with #1700. This PR closes #1703.
2. #1701: **probe once, then document.** The probe is a script the user runs
   against a test PR; agents never run it. If the App token is refused, the
   fallback is a repository ruleset that requests Copilot review. This PR
   refs #1701; it closes after the probe result is recorded.
3. #1702: **script and runbook, no web route.** A manifest JSON and a small
   CLI that converts the manifest code into a Secret manifest file. This PR
   closes #1702.
4. #1700: **deferred** until Factory RFC-0020 Phase 3; a comment says so.

## Design

### #1703 clone PAT

- `docs/compliance/control-objectives.toml:78` (`wiring.live_overlay` claim):
  replace "stored per-project clone PATs are unchanged (follow-up)" with an
  accepted-risk sentence: a stored clone PAT is read only at project add for
  the clone, in `GIT_ASKPASS`, never pushes; it stays encrypted at rest; using
  the App token instead is #1700. Regenerate the matrix with
  `scripts/gen_autonomy_matrix.py` (it writes
  `docs/docs/compliance/autonomy-matrix.md` and
  `docs/static/compliance/autonomy-matrix.json`).
- `docs/docs/concepts/github-app.md`: new section "Clone credentials". With
  no stored credential, a clone of an https github.com remote already uses
  the App token: `_run_git` wraps every git call in `github_env`
  (`project_workspace_service.py:439-470`, `apps/backend/core/git_credentials.py:53`).
  Moving a project = the App is installed on the repo, re-add the project
  without a stored credential, delete the PAT
  (`DELETE /api/git-credentials/{id}`, `routes/git_credentials.py:184`) and
  revoke it on GitHub. Keep a PAT only for repos the App cannot be installed on.
  The "Limits" bullet at `:76` points to this section.

### #1701 Copilot probe

`scripts/github_app_setup.py probe-copilot --repo OWNER/NAME --pr N
--app-id ID --installation-id ID --key-file PEM`:
mints an installation token the same way as the server (`_mint`,
`apps/web-server/server/services/github_app.py:79-97`: RS256 JWT with
`python-jose`, `POST /app/installations/{id}/access_tokens`), then POSTs
`{"reviewers": ["copilot-pull-request-reviewer[bot]"]}` to
`/repos/{repo}/pulls/{pr}/requested_reviewers` (same body as
`pr_endgame.py:740-760`). It prints the HTTP status and whether a Copilot
login is in the response's `requested_reviewers`. Exit 0 only for 2xx with
Copilot listed; else exit 1 and print the ruleset fallback. The token and
key are never printed.

Runbook section "Copilot review": how to run the probe, where to record the
result (#1701), and the fallback: a branch ruleset with "Automatically
request Copilot code review". Copilot gates only with
`AIFACTORY_PR_REVIEWER=copilot`; a missing review times out to a human stop.

### #1702 manifest flow

- `scripts/github-app-manifest.json`: name, url, `hook_attributes`
  `{"url": ..., "active": false}`, `redirect_url`, `public: false`,
  `default_permissions` `contents: write`, `pull_requests: write`,
  `metadata: read`, `default_events: []`. Same permissions as runbook
  section 1; no administration.
- `scripts/github_app_setup.py manifest [--org ORG] [--workflows] --out FILE`:
  writes an HTML page with a form that POSTs the manifest to
  `https://github.com/settings/apps/new` (or
  `/organizations/ORG/settings/apps/new`). `--workflows` adds
  `workflows: write`. The operator opens the file, creates the App, and
  copies `code` from the redirect URL (no local server).
- `scripts/github_app_setup.py convert CODE --out FILE`:
  `POST https://api.github.com/app-manifests/{code}/conversions` (no auth),
  writes a `v1 Secret` YAML named `aifactory-github-app` with key
  `private-key` (the chart defaults, runbook section 3) to FILE, created
  `0600` with `O_EXCL` (refuses to overwrite). Prints app id, slug and the
  install URL `<html_url>/installations/new`. Installation id stays a manual
  step (read from the URL after install). Never calls kubectl.
- Standard library only for `manifest`/`convert` (urllib); `probe-copilot`
  imports `jose` lazily, so the first two run on any Python 3.
- Runbook section 1 gains "Register with the manifest" before the manual steps.

## Alternatives rejected

- #1703 B (`kind="github_app"` clones): needs per-call tokens; that is #1700.
- #1703 C (remove stored PATs): breaks private repos outside the App installation.
- #1701 with a PAT: brings a PAT back into the pod (#1671).
- #1702 web route: a new unauthenticated callback and a key in the DB.
- Running the probe from this lane: it needs the user's live App credentials.

## Risks

- The probe result is unknown until the user runs it; docs say so.
- The manifest flow details (redirect with `code`, one-hour code expiry) are
  from GitHub docs; the convert step is not run in CI (network). Tests cover
  the pure parts only.
- Secret file holds the PEM: written `0600`, never overwritten, never printed.
