# Spec: 503 with the reason when the build backend refuses a launch

## Design

- `server/error_ref.py`: `async def build_backend_unavailable(_request, _exc) -> JSONResponse`
  returning `503` with a fixed `detail` (`BUILD_BACKEND_UNAVAILABLE`): "Build
  backend unavailable: set AIFACTORY_BUILD_BACKEND to 'subprocess', or to
  'kubejob' with DATABASE_URL set". The exception text never reaches the
  caller (Gate 5, raw exception in response; revised after the lead's review).
- `services/build_backend.py` `backend_config_error`: drop the raw env value
  (`{raw!r}`) from the unknown-value message; `selected_backend` already logs it.
- `server/main.py` `create_app`: `app.add_exception_handler(BuildBackendUnavailableError, build_backend_unavailable)`.
- The handler only sees the error if it leaves the route, so each launching
  `try` gets `except BuildBackendUnavailableError: raise` ahead of its generic
  `except Exception`: `routes/execution.py` spec creation (~600), delegation
  (~791), start (~827), create-and-run (~1272), trusted-plan build (~1518);
  `routes/from_issue.py` (~613).
- Not `execution.py` ~1450: that `try` writes the trusted-contract record and
  never launches a build.

## Alternatives rejected

- Per-route `HTTPException(503, ...)` in each `except`: six copies of the
  status and message mapping instead of one.
- Teaching `client_error` the type: it returns text and cannot set the status.

## Risks

None beyond the status change; clients that retried on 500 also retry on 503.

## Verification

`tests/test_build_backend_503.py`, end to end through `create_app()` with a
`TestClient` (auth disabled, agent service stubbed to raise): 503 and the
fixed detail on `/start` at all three re-raise sites (spec creation,
delegation, build), `/create-and-run`, `/from-plan` (trusted-plan build) and
`/from-issue`. The response never contains the exception text.
