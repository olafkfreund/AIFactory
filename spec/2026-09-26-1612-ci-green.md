# Spec: replace the gated object store, name the DB driver, and fail loudly not fatally

## Design

Two independent fixes, plus the fragility fix the intent requires.

### 1. Object store: SeaweedFS in place of MinIO

MinIO's images are gated at every registry (`quay.io/minio/minio` and
`docker.io/minio/minio` both 401 anonymously; quay denies even the tag list), so
this is a substitution, not a registry change.

**`chrislusf/seaweedfs` is the replacement, chosen by experiment rather than
argument.** Both S3 integration tests were run against it locally and passed:

```
tests/test_workspace_store_integration.py::test_round_trip_against_live_minio PASSED
tests/test_workspace_store_integration.py::test_partial_upload_simulation_against_live_minio PASSED
2 passed in 1.11s
```

That includes `test_partial_upload_simulation…`, whose docstring says it
"defends the partial-upload-detection contract against real S3 listing behavior"
— the property a mock would most plausibly weaken. SeaweedFS is a real object
store with a real S3 gateway, which is why it holds where `adobe/s3mock` would
have had to be taken on trust.

Operationally it is *simpler* than what it replaces:

- `docker run -d -p 8333:8333 chrislusf/seaweedfs:<pinned> server -s3`
- S3 endpoint answers HTTP 200 in **5 seconds** (MinIO's loop allowed 30)
- the bucket is created with a plain `curl -X PUT http://localhost:8333/<bucket>`,
  so the `mc` client the module docstring describes is not needed
- credentials are accepted as supplied; the tests pass their own

Note for implementation: `-dir` must point at a directory that exists in the
image. `-dir=/tmp/sw` fails with `Check Meta Folder … no such file or directory`
and the container exits 255. Omitting `-dir` uses the image default and works.

The image is pinned **by digest**, per the intent's constraint, so the next
vendor policy change is a deliberate bump rather than an outage.

Rejected: `adobe/s3mock` (a mock — cannot be trusted for the listing-semantics
test without proving it, and proving it costs the same as just using a real
store); `localstack/localstack` (faithful but far heavier for two tests).

### 2. The step must not be able to fail the job

This is the part that matters more than the image, and the intent is explicit
about it: the step's own comment already claims an unavailable MinIO makes the
tests "skip", but `docker run` exits 125 and takes the job down. It has now cost
two outages — `bitnami/minio` retiring mid-2026, and this one.

The start step becomes non-fatal and **reports what it did**:

- the `docker run` and the readiness loop cannot fail the step
- on success it exports the endpoint the tests key on and says so
- on failure it prints a `::warning::` naming the registry error, leaves the
  endpoint env unset, and continues

The tests already skip when `TEST_S3_ENDPOINT_URL` is absent
(`tests/test_workspace_store_integration.py:63,88`), so an unavailable store
degrades to exactly the documented behaviour instead of a red job.

**The skip must be visible, not silent** — the intent's binding constraint, and
the same rule as #597/#1496. A `::warning::` annotation appears on the run, so a
skipped S3 suite is legible in the UI rather than inferred from a passing job.

**`main` is stricter.** `ci.yml` triggers on `push` to `main` as well as PRs
(`ci.yml:5-7`), so a blanket tolerance would let a release build silently lose
its S3 coverage. On `main` an unavailable object store **fails** the step: on a
PR the tolerance keeps unrelated work merging, but nothing should be released on
evidence that was never gathered. This answers the intent's open question 3.

### 3. Postgres: name the driver

Seven copies of `_sync_url()` in `tests/postgres/` do
`url.replace("+asyncpg", "")`, producing a bare `postgresql://` URL and delegating
the driver choice to SQLAlchemy. That default changed between 2.0 (psycopg2,
installed) and 2.1 (psycopg v3, not installed), and
`apps/web-server/requirements.txt:60` has no ceiling.

The fix is to say what the suite means:

```python
url.replace("+asyncpg", "+psycopg2")
```

Verified: `postgresql+psycopg2://…` resolves to
`sqlalchemy.dialects.postgresql.psycopg2` irrespective of the default.

**Defined once, not seven times.** The seven identical copies are why a
one-line defect needed seven edits; a single `sync_url()` in
`tests/postgres/helpers.py` (which already holds the URL helpers) replaces them.

**SQLAlchemy is not pinned.** Naming the driver removes the dependency on the
default entirely, so a ceiling would add a stale pin without adding safety. This
answers the intent's open question 2.

## Alternatives rejected

**Add `psycopg[binary]` to the test requirements.** Follows the new default
instead of removing the dependency on it, and leaves the suite silent about
which driver it wants — so the next default change breaks it again.

**Pin `sqlalchemy<2.1`.** Freezes the suite against an upgrade the production
code has not rejected, and treats the symptom. The production requirement is
deliberately a floor.

**Authenticate to quay.io for MinIO.** Requires a credential the repo does not
have, ties CI to a vendor's commercial terms, and leaves the fragility in place.

**Fix the registry only, leave the step fatal.** The explicit "fix the registry
again without fixing the fragility just queues up a third outage" the intent
warns against.

**Vendor a MinIO image into GHCR.** Redistribution of a gated image, with the
licensing question that implies. Not for a test fixture.

## Risks

- **A tolerant step hides a genuinely broken object store.** Mitigated by the
  `::warning::` annotation and by `main` remaining strict. Accepted for PRs:
  a lint job should not be red because a third party changed its terms.
- **SeaweedFS's S3 semantics differ from MinIO's somewhere the two tests do not
  reach.** Both current tests pass; a future S3 test could meet a difference.
  The pinned digest makes the surface stable, and the failure would be a normal
  test failure, not an outage.
- **`-dir` misconfiguration exits 255**, which under the new tolerance would read
  as "store unavailable" and skip. The warning text names the container's exit
  and log so this is diagnosable rather than mysterious.
- **Changing all seven `_sync_url()` call sites** could miss one. The helper is
  imported, so a missed copy is a visible duplicate rather than a silent
  divergence, and the postgres jobs exercise every file.
- **Blast radius:** CI configuration and test helpers only. No production code,
  no runtime dependency, no deployment, no schema.

## Verification

1. **The S3 tests pass against SeaweedFS.** Already demonstrated locally (2
   passed); to be re-demonstrated in CI on the PR.
2. **The postgres jobs go green** on both PG 15 and PG 16 — the failure is
   `ModuleNotFoundError: No module named 'psycopg'`, so success is the whole
   proof.
3. **`backend (ruff + pytest)` goes green**, which it cannot today because the
   job dies at step "Start MinIO" before pytest runs.
4. **The tolerance is proven, not assumed.** A deliberate run with an
   unresolvable image must show: step succeeds, `::warning::` present, the two
   S3 tests reported as *skipped*, job green. Without this the fragility fix is
   itself untested.
5. **`main` strictness is proven** by the same unresolvable-image run evaluated
   against the `main` condition, so the branch asymmetry is not just asserted.
6. **No `_sync_url` copies remain:** `grep -rn "def _sync_url" tests/postgres/`
   returns nothing.
7. **The full suite still passes locally**, and cq-ratchet reports "0 regressed"
   on both halves for the changed Python.
