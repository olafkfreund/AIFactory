# Spec: Per-dispatch scoped S3 credentials for agent Jobs

## Design

MinIO STS `AssumeRole` with an inline session policy.

- New `apps/web-server/server/services/job_s3_scope.py`:
  `scope_job_s3(env, ids)`. When `AIFACTORY_SCOPED_JOB_S3` is true it calls STS
  (boto3 `sts` client against `S3_ENDPOINT`, signed with
  `S3_STS_ACCESS_KEY` / `S3_STS_SECRET_KEY`), then in the Job env removes
  `S3_ACCESS_KEY` / `S3_SECRET_KEY` and sets `AWS_ACCESS_KEY_ID`,
  `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`. Flag off: no-op.
- `ArtifactStore` (vendored, untouched) passes `None` keys to boto3 when
  `S3_ACCESS_KEY` is unset, so boto3's env chain supplies the session creds.
  No Job-side code change.
- Session policy: Allow `s3:GetObject`, `s3:PutObject`, `s3:PutObjectTagging`
  (put_bytes tags lifecycle objects) on `arn:aws:s3:::<bucket>/<prefix>/*` for each
  `(correlation_key, job_id)` pair, where the prefix comes from
  `ArtifactRef(...).prefix()` so the key layout stays single-sourced. No List.
  Ids containing `* ? / " \` or empty are refused (no wildcard injection).
- Build Job pairs: `(correlation_key, task_id)` (packed workspace) and
  `(None, spec_id)` (usage, plan, task logs, gate marker, memory).
  Spec Job pairs: `(None, "<task_id>-spec-<fetch8>")` (workspace) and
  `(None, fetch_id)` (spec files).
- Lifetime: build deadline (6h) plus 1h. Fail closed: flag on and the STS
  user unset or the call failing raises `BuildBackendUnavailableError`.
- Why a non-root user: MinIO refuses AssumeRole for the root credentials, so
  factory-gitops creates user `aifactory-sts` with a policy limited to
  `factory-artifacts/aifactory/*` (Get/Put/PutObjectTagging). The session
  policy narrows that further per dispatch. The control plane keeps the root
  key for its own pack/fetch; unchanged.

## Alternatives rejected

- Presigned GET/PUT URLs: needs no MinIO user, but every Job-side site
  (unpack plus six push helpers, spec files) changes from `ArtifactStore` to an
  HTTP client, and the vendored store cannot take it. Much larger diff.
- A MinIO user per task: creates and must reap long-lived credentials.
- Prefix-wide `aifactory/*` policy: still cross-task.

## Risks

- STS credentials expire: a Job that stays Pending past the lifetime cannot
  unpack. Mitigated by the +1h margin; the failure is loud.
- Prefix `aifactory/<corr>/<id>/*`: ids are unique per task; distinct ids
  cannot match each other's prefix because the policy ends the id with `/`.
- Needs the owner to set `minio-creds` keys `STS_ACCESS_KEY`/`STS_SECRET_KEY`
  and the control-plane env; until then the flag stays off.
- The Job can still tamper with its own task's keys; the control-plane fetch
  validation (#1932) remains the defence for that.

## Verification

Unit tests: policy content and resources, wildcard refusal, flag off no-op,
env swap, fail closed, both dispatch sites. `pytest` on the touched test files
and `ruff`. A live MinIO check is the owner's step after the gitops sync.
