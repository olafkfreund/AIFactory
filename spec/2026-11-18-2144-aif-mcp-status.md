# Spec: Real status, logs and running list for kubejob builds

## Design

1. `/running`: `AgentService.get_running_task_ids()` returns in-pod builds plus `_active_kubejob_task_ids` (the set `is_running` already consults, #1619). The route and the MCP proxy use it. WebSocket callers keep `get_running_tasks()`.
2. `/status`: `TaskExecutionStatus` gains `queued`, `overall_progress`, `current_subtask` and fills `phase`/`message`. Phase order: `queued` first when the task is in the admission queue or its durable row is `queued` (a retry can still carry an old `task_logs.json` phase); else `executionProgress.phase` from the same `get_task` path the portal uses (`task_to_dict`); else `starting` when running with no progress; else null. `message` is the progress message ("x/y subtasks completed").
3. `/logs`: eligibility is by content, not file presence (dispatch creates an empty `task_logs.json`): when the result has no phase entries and no legacy logs, and the durable row is a `k8s-job` ref, tail the Job pod (`build_log_stream.tail_job_logs`, `tail_lines`, bounded 500) and redact the marker nonce (`AgentService._redact_nonce`) from every line, and return it as `logs` entries with `source: "job"` (also on the phases-shaped result). The route gains `tail`; the MCP proxy forwards it.
4. MCP `agent_status` reads `overall_progress` / `current_subtask` now present in `/status`; `task_running` output unchanged in shape.

## Alternatives rejected

- MCP-only derivation: the portal would stay wrong and two derivations would drift.
- Persisting a log buffer in the DB: new storage for an observability read.
- Reading logs from `task_logs.json` only: that file is exactly what is missing on the packed path.

## Risks

Codex review (confirmed, folded in): nonce redaction, content-based eligibility, queue precedence.


Pod log read needs `pods/log` RBAC (already used by the log streamer). A failed read degrades to the old empty result. `/status` does one extra file read per poll.

## Verification

Per tool, with a kubejob-backed fixture (task in `_active_kubejob_task_ids`, plan/task_logs on disk, fake pod log reader): running lists it; status returns phase/progress/queued; logs return the pod tail; `agent_status` shows phase and progress.
