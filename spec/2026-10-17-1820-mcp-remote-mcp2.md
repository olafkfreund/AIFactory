# Spec: port mcp-remote to the mcp 2.x server API

## Design

API checked against an installed `mcp==2.0.0` (scratch venv from
`requirements.lock`), `mcp/server/lowlevel/server.py`:

- `Server(name, *, version=..., on_list_tools=..., on_call_tool=..., ...)`;
  no decorator methods.
- `on_list_tools(ctx: ServerRequestContext, params: PaginatedRequestParams |
  None) -> ListToolsResult`.
- `on_call_tool(ctx, params: CallToolRequestParams) -> CallToolResult`;
  `params.name`, `params.arguments`.
- `CallToolResult(content=..., is_error=...)`; pydantic models take
  snake_case names or the camelCase alias (`Tool(inputSchema=...)` still
  works).
- `Server.run(read, write, init_options)`, `create_initialization_options()`,
  `SseServerTransport(endpoint)`, `connect_sse`, `handle_post_message` keep
  their 1.x shape.

Changes:

1. `apps/web-server/server/mcp_remote/server.py`
   - `_list_tools(ctx, params) -> ListToolsResult(tools=[Tool(...)])` from
     `get_tool_definitions()` as today.
   - `_call_tool(ctx, params) -> CallToolResult`: missing key still returns
     an error text block (now also `is_error=True`); otherwise
     `dispatch_tool_call(params.name, params.arguments, key)` and map its
     `content` blocks to `TextContent`, carrying the envelope's `isError`
     (`tools.py:79-81`) to `is_error` (1.x dropped it).
   - Build `_mcp_server = Server("aifactory-remote", version="1.0.0",
     on_list_tools=_list_tools, on_call_tool=_call_tool)` after the handlers.
   - `sse_endpoint` passes `_mcp_server.create_initialization_options()`;
     drop the `InitializationOptions` / `NotificationOptions` imports.
   - Auth contextvar flow unchanged.
2. `apps/web-server/requirements.txt`: declare `mcp>=2.0` (the web-server
   imports it directly). Regenerate `requirements.lock` with the command in
   its header; only the `# via` comments of `mcp` change.
3. Test `apps/web-server/tests/test_mcp_remote_import.py` (run by
   `ci.yml:218`): with `AIFACTORY_MCP_REMOTE_ENABLED=true`,
   `server.main.create_app().openapi()` has `/api/mcp-remote/sse` and
   `/api/mcp-remote/messages/`; and the two handlers return the tool catalog
   and refuse a call with no key.
4. `scripts/generate-openapi-spec.py`: delete the override at `:54-55`;
   add `AIFACTORY_MCP_REMOTE_ENABLED` to the opt-in `description`.
   Regenerate `openapi.yaml` (must not change) and `openapi-optin.yaml`
   (gains the two paths).
5. Docs: drop the "left out until #1820" sentence in `docs/api.md:28-29` and
   mention the remote MCP transport in the `aifactory-web-api-optin`
   description in `catalog-info.yaml:119-124` and the entity comment `:16`.

## Alternatives rejected

- Pin `mcp<2`: the lock already ships 2.0.0 and `claude-agent-sdk` pulls
  mcp too; holding it back fights two dependents.
- Support 1.x and 2.x with a version branch: more code for an env the lock
  never builds; the floor makes the mismatch an install error instead.
- Rewrite on `MCPServer` (high-level) or streamable HTTP: a transport change,
  out of scope.

## Risks

- `Server.run` in 2.x serves both handshake eras; the SSE route is unchanged,
  but no end-to-end SSE client test exists. Covered: import, route mount and
  handlers. Not covered: a live SSE session (needs a DB-backed `acw_` key).
- Local venvs on mcp 1.x fail the new test until reinstalled from the
  requirements (intended by the floor).
