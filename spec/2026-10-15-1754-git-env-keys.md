# Spec: refuse git config and exec env keys wherever a variable is set

## Design

One check, `_env_key_refusal(assignment)` in
`apps/backend/security/ast_parser.py`, takes `NAME=value` (or a bare `NAME`)
and raises `UnparseableCommand` when NAME is not allowed. It runs at every
place the parser sees a variable being set:

1. **Assignment nodes.** In `_extract` (`:174`), for every `assignment` part of
   every command node, before the "no words" skip. Covers prefix
   (`K=v git`) and standalone (`K=v; git`) assignments, at any depth
   (`bash -c` payloads and substitutions are re-walked already).
2. **`env` assignments.** In `_unwrap_env` (`:295`), the `VAR=val` branch.
3. **Variable-setting builtins.** In `_emit` (`:186`), when the command is one
   of `export read let declare typeset local readonly mapfile readarray
   getopts`, each non-option argument is a name: its raw text must be a static
   shape (`_static_shape`) or start with a literal `NAME=`/`NAME+=` (so
   `export PATH="$HOME/bin:$PATH"` passes, `export $K=1` and `read "$V"`
   fail closed), and its name goes through `_env_key_refusal`. Option words
   must be literal; `-n` (nameref) on `declare`/`typeset`/`local` is refused.
   For `printf`, only the `-v NAME` (or `-vNAME`) target is checked.

4. **Removing the pins.** `core/child_env.py` exports `GIT_CONFIG_*` pins
   (`core.hooksPath=/dev/null`, `core.fsmonitor=false`, …) into the agent
   env. `unset`, `export -n`, `env -u` of a refused key, and clearing the
   env (`env -i`, `env -`, `--ignore-environment`, `exec -c`) are refused.
   (Added at plan time.)

### The key rule (allow lists)

- `GIT_*`: refused unless in `_SAFE_GIT_KEYS`:
  - `GIT_AUTHOR_NAME/EMAIL/DATE`, `GIT_COMMITTER_NAME/EMAIL/DATE`: commit
    metadata only.
  - `GIT_TERMINAL_PROMPT`: only disables prompting.
  - `GIT_OPTIONAL_LOCKS`, `GIT_FLUSH`: locking and output buffering.
  - `GIT_MERGE_AUTOEDIT`: `no` skips the editor; any value runs nothing new.
  - `GIT_LFS_SKIP_SMUDGE`: skips LFS downloads.

  Everything else is refused, including keys not listed in the issue. Unsure
  keys are refused: `GIT_TRACE*` (writes to a path the value names),
  `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR` (point git at another repo and
  its config), `GIT_CONFIG*`, `GIT_CONFIG_PARAMETERS`, `GIT_SSH*`,
  `GIT_EXEC_PATH`, `GIT_ASKPASS`, `GIT_PROXY_COMMAND`, `GIT_EXTERNAL_DIFF`,
  `GIT_TEMPLATE_DIR`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`.
- Program keys `GIT_PAGER`, `GIT_EDITOR`, `GIT_SEQUENCE_EDITOR`, `PAGER`,
  `EDITOR`, `VISUAL`: git runs the value as a command, so only the no-op
  values `cat`, `true`, `:` or empty are allowed (a bare `export EDITOR` is
  allowed; it sets no value).
- `SSH_ASKPASS`: refused (git runs it when `GIT_ASKPASS` is unset).
- Any other name: allowed.

## Alternatives rejected

- Refuse all `GIT_*`: breaks `GIT_PAGER=cat git log` and
  `GIT_AUTHOR_NAME=x git commit`.
- A deny list of the keys named in the issue: misses keys added later and
  ones not listed (#1782's lesson).
- Pass the assignments to the git validator: it would not see `export K=…;
  git` in a later command, or keys set for `bash -c 'git …'`.
- Scan every word for a key name: refuses `echo GIT_DIR` and still misses a
  dynamic name.

## Risks

- `HOME`, `XDG_CONFIG_HOME`, `PATH`, `LD_PRELOAD`, `BASH_ENV` still let the
  agent point git (or anything) at a config file or binary it wrote. Per
  #1782's trust boundary that is trusted file content, the same as
  `bash s.sh`; not covered here (see #1745 for agent-writable git config).
- The agent env carries `GIT_CONFIG_*` pins from `core/child_env.py`, so a
  plain assignment to those keys changes an exported value; the rule refuses
  it in every form.
- `read -p "$PROMPT" x` is now refused (dynamic word in a name position).

## Verification

- Refused (`GIT_RCE_PAYLOADS`, validator and hook): the issue's example bare
  and via `env`; `export GIT_CONFIG_COUNT=1; git status`;
  `env GIT_SSH_COMMAND='nc x' git fetch`; `GIT_DIR=/tmp/x git status`;
  `GIT_PAGER='nc x' git log`; `GIT_EXEC_PATH=. git status` inside `bash -c`;
  `export $K=1`; `read GIT_DIR`; `printf -v GIT_DIR x`;
  `let GIT_CONFIG_COUNT=1`; `SSH_ASKPASS=x git push`; `EDITOR=vim git commit`;
  `GIT_TRACE=/tmp/t git status`.
- Allowed (`MUST_PARSE`, exact names): `GIT_PAGER=cat git log`,
  `GIT_AUTHOR_NAME=x git commit -m m`, `GIT_EDITOR=true git rebase --continue`,
  `FOO=$BAR git status`, `export PATH="$HOME/bin:$PATH"`,
  `printf '%s\n' "$X"`, `read -r line`.
- Unchanged: the full security, hook and sandbox set.
