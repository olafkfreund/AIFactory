# Spec: upload LFS objects on the remaining push sites and ship git-lfs

## Design

### D1. One shared upload routine in `core/child_env.py`

Add, next to `lfs_push_argv` (`apps/backend/core/child_env.py:88`):

```python
LFS_UPLOAD_TIMEOUT = 600

def lfs_upload(run: Callable[[list[str], int], tuple[int, str, str]], ref: str) -> str | None:
```

`run(argv, timeout)` runs one git command in the repo being pushed, with the
push's env, and returns `(returncode, stdout, stderr)`. Each site supplies its
own `run`, so tests that fake `subprocess.run` or the pr_endgame `runner`
keep working. Steps, in order:

1. **Gate (new):** `git grep -q -F -e filter=lfs <ref> -- ':(glob)**/.gitattributes'`
   (timeout 60). rc != 0 (no match, or the check could not run) returns
   None: the repo does not use LFS at that ref, so nothing changes for it.
2. `git remote get-url --push --all origin` (60). rc != 0 returns None (as #1690).
3. `lfs_push_argv(out.strip(), ref)`; None returns None (git-lfs missing, or
   not a plain github.com origin, as #1690).
4. `git config --name-only --get-regexp '^(lfs\.customtransfer\.|url\.)'` (60).
   rc != 1 returns `"LFS step refused (lfs.customtransfer.* or url.* defined)"`.
5. The pinned upload, timeout `LFS_UPLOAD_TIMEOUT`. rc != 0 returns
   `stderr.strip() or "git lfs push failed"`.

Returns None when the objects are uploaded or no upload is needed.
`subprocess.TimeoutExpired` propagates; every site already handles it.

`apps/web-server/server/utils/subprocess_env.py` re-exports `lfs_upload`
beside `lfs_push_argv`.

### D2. Web-server sites call it (gate + longer timeout reach them)

- `pr_endgame.push_with_lfs` (`pr_endgame.py:81-111`) becomes: build `run`
  from `runner`, call `lfs_upload`, return `CmdResult(1, "", err)` on error,
  else `runner(push_argv, cwd)`. `_default_runner` gains `timeout: int = 120`;
  `push_with_lfs` passes the timeout only when `runner is _default_runner`
  (injected test runners keep their two-argument signature).
- `routes/pr.py:322-368`: the inline copy is replaced by a local `run` over
  `subprocess.run(..., cwd=worktree_path, env=env, timeout=t)` and one
  `lfs_upload(run, worktree_branch)` call. Error text becomes
  `"Failed to push LFS objects: <err>"` for both refusal and upload failure;
  the refusal message still contains "LFS step refused".

### D3. Backend sites call it

- `core/workspace_fetch.py:135-146`: inside `with authed_push_url(url) as
  (push_url, git_env)`, before the push, `lfs_upload(run, "HEAD")` with
  `run` over `subprocess.run(cwd=wt, env=git_env)`. On error: log a warning
  and return False (best-effort, no push of a branch with missing objects).
- `pfactory/tfactory_client.py:382-396`: same, `lfs_upload(run, sha)` with
  `cwd=repo, env=git_env`. On error: log a warning and `return url, None`
  (the existing "build did not land" outcome).

The upload uses the same `git_env` as the push, so the credential reaches
git-lfs through the per-call `GH_CONFIG_DIR` helper, never argv or env.

### D4. Image

`Dockerfile:175-187`: add `"git-lfs>=3.7.1"` to the apk list (the pinned
base's Wolfi index has 3.7.1-r2 through 3.8.0-r3; checked with `apk policy
git-lfs` in the pinned base). Then `RUN git lfs install --system --skip-smudge`:
the Wolfi package writes system `filter.lfs.*` with smudge on and
`required=true`, so without `--skip-smudge` every clone of an LFS repo would
start downloading objects and fail when it cannot. The clean filter stays on,
so a new LFS-tracked file is stored as a pointer plus a local object, which
D1 then uploads.

## Alternatives rejected

- **Gate inside `lfs_push_argv`:** it has no cwd/ref; changing its signature
  breaks every #1690 test for no gain over D1.
- **Gate on the working tree's `.gitattributes`:** `tfactory_client` pushes a
  sha from a repo whose checkout can be the base branch; grepping the pushed
  ref is exact and one command.
- **Raise every runner timeout to 600 s:** a hung `gh` would then block 10 min.
- **Keep smudge on:** changes clone behaviour for every LFS repo; out of scope.
- **Treat an LFS failure as a warning and push anyway:** the issue's
  acceptance says a failed upload is a push failure.

## Risks

- A repo that uses LFS and also sets `url.*` config is now refused at the
  backend sites too (same as the web-server sites since #1690). Accepted: it
  is the #1690 security rule.
- An LFS repo whose objects are missing locally and on the server fails the
  upload (`allowincompletepush=false`) where it silently "worked" before.
  That is the bug being fixed.
- Non-github.com origins never upload (unchanged from #1690, see the GATE
  note in the issue).

## Verification

- Unit: `lfs_upload` skips every step after the gate when the gate fails;
  runs gate, get-url, check, upload in order and passes `LFS_UPLOAD_TIMEOUT`
  to the upload; returns the refusal / stderr.
- Real git: a repo without `filter=lfs` returns None after one command; with
  a committed `.gitattributes` containing `filter=lfs` it proceeds.
- Sites: `maybe_push_workspace_branch` returns False and does not push when
  the upload fails; `_git_info_and_push` returns `(url, None)` and does not
  push when the upload fails.
- Existing #1690 tests in `tests/test_lfs_push.py`,
  `tests/test_create_pr_fetches_branch.py`, `tests/test_pr_endgame_conflict_loop.py`,
  `tests/test_completion_lands_via_merger.py`, `apps/web-server/tests/test_pr_endgame.py`
  pass, with their fakes answering the gate.
- Image: `apk add git "git-lfs>=3.7.1" && git lfs install --system --skip-smudge`
  succeeds in the pinned base.
